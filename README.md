# Star Citizen Japanese Text Creator

Star Citizen のゲーム内テキストを AI で日本語に翻訳し、ゲームに適用する Windows デスクトップアプリケーションです。
AI チャットによるゲーム情報検索、音声読み上げ、スマホからの利用にも対応しています。

> **📖 [図解つき 使い方マニュアル](https://batake321.github.io/StarCitizenJapaneseTextCreater/)** — インストールから翻訳の当て方、船舶管理・Web チャットまで一通り解説しています。初めての方はこちらから。

## 機能

- **Data.p4k 自動抽出** - ゲームの Data.p4k (ZIP64 + ZStd) から英語/日本語の global.ini を自動抽出
- **AI 翻訳** - Claude / Gemini / OpenAI / Ollama (ローカル LLM) の 4 バックエンドに対応、複数同時並列翻訳
- **翻訳エディタ** - AI 翻訳結果の確認・手動編集・検索 (ワイルドカード対応)・フィルタリング・原文維持
- **用語集** - 固有名詞の翻訳ルールを登録し、一括置換も可能。複数選択で一括削除
- **AI チャット + 音声読み上げ** - AI に Star Citizen の最新データを検索させて日本語で回答。VoiceVox による音声読み上げ対応
- **Web チャット (スマホ対応)** - ブラウザからチャット・音声入力が可能。HTTPS 対応でスマホのマイクも利用可
- **データ API (読み取り専用)** - Web チャットサーバーを起動している間、詳細タブ・交易・契約などのデータを JSON か HTML で読み出せます（下の「[データ API (読み取り専用)](#データ-api-読み取り専用)」）
- **ナレッジ (記憶)** - AI に情報を教えて記憶させる機能。バグ情報・用語・Tips を保存し、チャットに自動反映
- **ロケーション検索** - ステーション・都市の施設情報（精錬所・ハンガー・エレベーター等）を Star Citizen Wiki API + UEX から統合取得
- **コモディティ交易** - UEX 価格データから最適ルート自動計算、在庫・コンテナサイズ表示、所持船管理、AI チャット連携
- **価格キャプチャ** - ゲーム画面をキャプチャし、OCR で価格を読み取って UEX に送信します（PrintScreen のホットキー、手動キャプチャ、クリップボード・ファイルからの読み取り。設定タブの「UEX 価格送信 (Screen Capture)」に UEX API Key を入れます）
- **キーバインドエディタ** - キーボード・マウス・ゲームパッド (Xbox)・HOTAS (左右のスティック) のビジュアル表示、activation mode 色分け、翻訳連携。HOTAS・ゲームパッドのボタンを押して割り当てられます
- **契約一覧** - Data.p4k から全契約を抽出し、カテゴリ別に一覧表示。報酬・レピュテーション要件/報酬・前提契約・敵構成・制限時間など詳細情報を表示
  - **契約の地図**: 契約の詳細の後ろに「■ 地図」の節を出します。行き先の地図の場所が 10 か所以下なら、場所の名前（英語のまま）がリンクになります。押すと、その場所のステーションの 3D が出ます（別ウィンドウが開いていればそこに、無ければ［マップ］タブに）。11 か所以上なら「候補 N か所」と数だけ出します。まとめた行では、まとめた全部の契約の地図を合わせて出します（10 か所の決まりは合わせた数に当てます）
  - **※ 行き先の場所は、契約の条件（タグ）からアプリが探したものです。実際の行き先と違うことがあります。参考としてお使いください**
  - 場所の一覧に出ない場所（洞窟・残骸・墜落現場、星図に載っていない場所のうち床の形が無い場所）と、名前の無い場所へのリンクは出しません。出す場所が無い契約には「■ 地図」の節を出しません
  - 行き先の地図の表は、インデックス構築で作ります。前の版で作った DB でも、起動の後に裏で作ります（Data.p4k があるとき。作れなかったときは次の起動でまた作ります）
- **船舶戦闘・個人戦闘** - 武器のダメージ表です（1 発のダメージ・バーストDPS・平均DPS・弾速・店の最安値など）。各列で絞り込み（含む/含まない）と、Shift+クリックで複数列の並べ替えができます。個人武器はダウンまでの発数も出します。［個人戦闘］の「ダメージ判定」タブでは、銃にスコープ・マズル・アンダーバレル・マガジンを付けたときの DPS・1 発のダメージ・弾速・ダウンまでの発数を、付けないときと並べて出します（補正の重ね方は推定）
- **船舶装備・個人装備** - ［船舶装備］はパワープラント・クーラー・シールド・レーダー・量子ドライブを出力・冷却・HP・速度などで、［個人装備］はアーマー・服・道具などをダメージ軽減・温度・容量などで比べられます。［個人装備］タブの下には、所持している個人装備（銃・アーマー・弾倉・消耗品など）の一覧があります
- **詳細** - 名前で検索して、説明文・性能・販売場所などを表で出します（分類・種類・サイズで絞り込める一覧つき。各タブの表の名前をダブルクリックしても開きます）。星系 → 惑星 → ステーション → 店 → 売り物（価格）とリンクでたどれ、［戻る］で 10 件まで戻れます。鉱石は採掘できる場所・掘り方（船 / ROC / 手）・出やすさ、船・車両は既定の装備の表、銃は装着できるアタッチメントの一覧も出します。採掘できない資源は、種類が「コモディティ」と出ます（【採掘できる場所】の節は出しません）。3D の欄（船・車両、武器・装備）は、詳細の文との間の線を上下にドラッグして高さを変えられ、変えた高さは覚えます（別ウィンドウの 3D は、窓の大きさを変えて使います）
- **ゲームデータ連携** - Data.p4k の DCB データベースからオンデマンドで船・武器・コンポーネント情報を取得
- **船舶管理** - ［所持船］［アップグレード管理］［装備］［電力管理］のタブで、持っている船と装備を管理します
  - **所持船**: 所持船の一覧です。入手の種類（pledge / ゲーム内購入 / ミッション）と期限を持ち、ゲーム内で買った船とミッションで得た船は、ゲームログから自動で入ります（行の「取り消す」で戻せます）。［ワイプ］で、ゲーム内購入とミッションの船を選んでまとめて消せます
  - **アップグレード管理（My Hangar 同期）**: 内蔵ブラウザ (WebView2) で RSI にご自身でログインすると、保有 pledge・船・保険・アップグレード権利 (CCU) を取得します（読み取りのみ）。アップグレードのシミュレーション（Upgrade・Undo）、売却 (melt) の試算、RSI ストアの販売情報を出します
  - **装備**: 所持コンポーネントと、船ごとの現在の装備を設定できます（未設定のポートは初期装備を表示）。自作したコンポーネントの品質も入れられます（電力管理の計算に使います）
- **電力管理** - 船の部品（パワープラント・クーラー・シールド・武器など）のピップの割り当てを変えて、出力の残り・冷却・シールド再生量・武器のサステイン DPS を見られます。自作したコンポーネントの品質も計算に入ります
- **プロファイル管理** - キャラクターデザイン・キーバインド設定のバックアップ/リストア
- **ゲームパス自動検出** - RSI Launcher のログから Star Citizen のインストール先を自動検出
- **チャンネル切替** - PTU / LIVE / EPTU など複数チャンネルをワンクリックで切替
- **新しいパッチの検出** - 翻訳タブの読み取りボタンに版を出し（例「4.10.2 LIVE を読み取る」）、LIVE・PTU に新しい版があれば黄色にします
- **ブループリント (BP)** - ゲームデータから BP の一覧・材料・製作時間・入手経路を出し、鉱石の在庫で作れるかを照合。材料を複数選んで「その材料で作れる BP」を探せます。品や契約の詳細にも BP の情報を出します。［詳細］タブの鉱石（資源）の詳細の最後には「この資源を使う BP」の節（その資源を材料に使う BP のできる品・分類・枠・量・最低品質。原石は精錬後の資源として引きます）を出します。持っている BP には「所持」の印が付き（ゲームログの「設計図を受信しました」から自動で入り、表のボタンで手でも入切できます）、所持している BP だけに絞り込めます。所持の記録はバックアップと PC 間の同期の対象です。BP の分類は［BP］タブ・詳細の BP の節とも日本語で出します（例 FPSWeapons → 個人武器、VehicleComponentS2 → 船舶装備 S2）。［BP］タブの検索・絞り込みの窓の検索は、英語の分類の値（FPSWeapons など）でも当たります
- **鉱石** - 採掘・積み荷の資源の在庫を「資源 × 品質」ごとに持ちます。採掘の拾得・積み荷の購入で増え、売却・納品で減ります（手入力で追加・編集・削除もできます）。売買の記録には、先入れ先出しで計算した仕入れ・利益・利益率を出します。採掘の記録もあります
- **ゲームログ** - Game.log から、死亡・衝突、契約の受注・完了・失敗、購入・売買、量子ジャンプ、区域への出入り、船の呼び出し・格納、乗船・下船、採掘、貨物エレベーター、納品などを表で出します（過去のログもまとめて読みます）。内容をダブルクリックすると品・船を［詳細］で開き、購入・採掘・降ろした品の行は「所持」の欄のボタンで所持・在庫に入れる／取り消すができます
- **ゲームログの音・読み上げ** - Game.log を追い読みし、船を操縦中に休戦ゾーンに入ったとき・着陸場に到着したときに音を鳴らします（ハンガーリクエストが出せる合図。徒歩で休戦ゾーンに入ったとき、ジャンプポイントの休憩所では鳴らしません）。設定タブで「VOICEVOX で読み上げる」を選ぶと、乗船・操縦席を離れた・量子ジャンプ・契約完了・採掘などの場面ごとに、文と声（VOICEVOX の話者）を決めて読み上げられます（到着は「Lorvilleに到着しました。」のように場所の名前入り。名前が分からない場所は名前を省きます）。VOICEVOX につながらないときは、休戦ゾーンと到着だけ音のファイルを鳴らします。倒した相手はゲームのログに出ないので読み上げられません。設計図（BP）を受け取ると「BP受信」の行を出し（直前に完了した契約があれば契約名も添えます。内容のダブルクリックでできる品の［詳細］）、その BP を［BP］タブの所持に自動で入れます。死亡したときは「死亡」の行（場所。船に乗っていたときは船も、衝突で死んだときは「（衝突）」も添えます）を、その後に生き返ったときは「復活」の行（復活した場所）を出します
  - **乗り降り**: 読み上げの場面「操縦席を離れた」の既定の文は「{船}の操縦席を離れました。」です（船が分からないときは「船の操縦席を離れました。」）。保存してある文が前の既定の文（「{船}から降りました。」「操縦席を離れました。」）のままなら、新しい文で読みます（「下船」の文は変えません）。「下船」は、ゲームが船のチャンネルの退出の通知を出さないときも推定で出します。操縦席を離れた後、操縦席に戻らないまま、ハンガーのエレベーターを使った・休戦ゾーンに入った（歩いて船の外に出た）ときや、着陸場所の中で区域を移ったときに「下船」の行（内容に「（推定）」を添えます）を出して読み上げます。同じ降りる動きで後から退出の通知が来ても、2 回は出しません
  - **読み上げる文を外のアプリに渡す**: 設定タブの「ゲームログの音」の「読み上げる先」で「VOICEVOX だけ」（既定）「外のアプリだけ」「両方」を選べます（「VOICEVOX で読み上げる」が入っているときに使います）。外のアプリの呼び方は exe と API から選びます
  - exe: 「exe のパス」と「exe の引数」（例 `/say "{talk}"`）を入れます。API: 「API の URL」（例 `http://localhost:50080/talk?text={talk}`）、「API の方法」（GET / POST）、POST のときは「POST の本文」（例 `{"text":"{talk}","scene":"{scene}"}`）を入れます
  - 置き換える値: `{talk}` = 読み上げる文、`{scene}` = 場面（表の場面の欄の名前）、`{speaker}` = その場面の声の VOICEVOX の話者 ID
  - 置き換えの規則: exe の引数では値の中の `"` を `\"` にし、`"` の直前の `\` も Windows の引数の規則で崩れないように打ち消します（`{talk}{scene}` のように欄を続けて書いても、置き換えた後の並びで判断します。値に空白があるときは `"{talk}"` のように `"` で囲んでください）。URL では値を URL 用に打ち消します（`Uri.EscapeDataString`）。POST の本文では値を JSON の文字列の中身として打ち消します（引用符は付かないので `"{talk}"` のように囲んでください。Content-Type は `application/json; charset=utf-8`）
  - 呼ぶ時期: 読み上げの順番が来たとき、VOICEVOX で鳴らす前に呼びます。exe は起動したら終わるのを待ちません。API は 5 秒まで応答を待ち、2xx 以外は失敗としてログに出します（応答の本文は使いません）。「両方」では外のアプリが失敗しても VOICEVOX で読み上げます。「外のアプリだけ」では VOICEVOX も音のファイルも鳴らしません。exe のパスか URL が空のときは呼ばずに「[読み上げ] 外のアプリの設定が空です」をログに出します。読み上げる文が空のときも呼びません（「外のアプリだけ」では「[読み上げ] 読まない（場面）: 読み上げる文が空です」を出します）
  - ログに出る失敗: 「[読み上げ] 外のアプリを呼べませんでした（場面）: 理由」（「外のアプリだけ」では「[読み上げ] 読まない（場面）: 外のアプリを呼べませんでした: 理由」）を毎回、「[ゲームログ] 外のアプリを呼べませんでした: 理由」を直前と理由が違うときだけ出します（呼べたら、次の失敗でまた出します）
  - ［試す］で、今の入力（保存前）で外のアプリを 1 回呼べます（`{talk}` = 読み上げのテストです、`{scene}` = テスト、`{speaker}` = 既定の声の話者 ID）。呼んでいるあいだと結果のメッセージを閉じるまでは［試す］を押せません
- **船の 3D 表示** - ［詳細］タブで船・車両を出しているとき、その船の 3D モデルを見られます。モデルはゲームデータ（選択中のチャンネルの Data.p4k）から取り込みます（テクスチャ付き・船内込み）。取り込んでいない船は、ゲームデータから直接読んで表示します。表示には同梱の three.js 0.186.1（MIT）を使い、ネットからは読みません。仮のモデル（名前に demo が入った部品。リレーの箱）は描きません
  - ［詳細］の船の欄: ［読み込み］でゲームデータから取り込み、［3D 表示］で下の欄に、［別ウィンドウ］で別の窓に出します（詳細の欄は表に戻ります）。3D を出している間は［表に戻る］で詳細の表に戻ります。［3D 表示］［別ウィンドウ］は、取り込み済みならそのモデルを、取り込んでいない船はゲームデータから直接読んで出します（「3D モデルを保存しない」を入れていなければ、読んだものを置き場所に置いておきます）
  - ［読み込み］は、その船の最新のモデルが無いときだけ押せます（取り込み済み・取り込み中は押せません）。押すと予想時間と予想サイズを出して確かめてから、裏で取り込みます（その間もほかの操作・ほかの船の取り込みができます）。終わったら、押した画面がまだその船ならそのまま表示します
  - 別ウィンドウ: 上の欄で船を切り替えられます。名前（英語名の部分一致）・メーカー・種類・サイズで候補を絞り込み、選ぶとその船に切り替わります（↓ で候補へ、Enter で最初の船）。取り込み済みの船はそのモデルを（Data.p4k が変わっていれば照合してから）、取り込んでいない船はゲームデータから直接読んで出します（状態の欄に「キャッシュなし (開いたときにゲームデータから直接読みます)」）。上の欄の［読み込み］は、取り込んで置き場所に保存するボタンです（「3D モデルを保存しない」のときは使えません）
  - 操作: 左ドラッグで回転（船外は船のまわりを回る／船内は見回す）、右ドラッグで平行移動、ホイールで拡大縮小（船内では前後移動）、W/A/S/D で前後左右、↑/↓ で上下、Insert/Delete で拡大/縮小（船内では画角）、Home で初めの位置。［船外］の初めの位置は左斜め前方の上から船全体を見下ろす位置、［船内］の初めの位置は操縦席です。船内は壁を通り抜けて動けます
  - 右の「船内の位置」: 操縦席・エレベーター・貨物室・タレット・医療ベッドと、部屋（船内の区画）のうちデータにあるものを並べます。医療ベッドを押すと、ベッドの横からベッドを見下ろす位置に移ります。部屋の名前は日本語にします（例 ブリッジ・機関室・浴室 (左)・貨物室 (前部)・居住区。全船 279 隻の区画の名前から作った語の表による）。表で日本語にできない名前は、AI 設定で有効な最初の翻訳バックエンドで訳して作業フォルダの `ship3d_room_names.json` に覚えます（ボタンの説明に「AI 訳」と出ます。バックエンドが無ければデータの名前のまま）。中身の無い区画は場所が分からないので出しません。部屋の位置は区画の範囲の真ん中から決めるので、船体の継ぎ目の外になる部屋もあります。同じ種類が 2 つ以上あるときは「▼ タレット (20)」のようにまとめ、押すと広がります（▲ で閉じる）。押すとその位置に移ります（船内の表示になります）。どれに当たるかは GLB のノード名で決めています
  - 取り込みの時間と大きさ（作者の PC での実測）: 1 隻 数秒〜数十秒、数十 MB〜数百 MB（例 X1 5 秒・26MB、600i 9 秒・147MB、Polaris 約 10 秒・648MB）。1 本の取り込みでメモリを最大 約 1.4GB（600i）〜2.9GB（Polaris）使います
  - **全部の船を取り込んだとき（作者の PC での実測、2026-10 の LIVE）**: ［船舶・車両をまとめて取り込む］で入る全部（279 隻）で 合計 25.9GB（設定タブの使用量の表示）。時間は、始める前の見積もり（船ごとにゲームデータの構成を調べる。1 隻 約 2 秒を同時に）と取り込みの合計で、作者の PC（同時 6〜7 本）では 約 9 分（見積もり 約 2 分＋取り込み 約 7 分。147 隻 12.2GB を見積もり 1 分 2 秒・取り込み 3 分 15 秒で入れた実測から、大きさの比で引き延ばした値）。同時に動かせる数が少ない PC では長くなります（1 隻ずつなら 約 45 分の見込み）。全部取り込むには、設定タブの最大容量を 30,000 MB 程度に上げてください
  - 進み具合: 船ごとのバーと全体のバーで、％と残り時間を出します（［詳細］タブと設定タブの「3D モデル」の欄の両方）。ゲームデータの大きさから見積もった時間と取り込みの段階から求めた**予想にもとづく値**です（終わるまでは 99% で止まります）。船ごとに取り消せます。予想の係数は、ほかと並行せずに取り込んだときの実績で直していきます
  - 同時に取り込む数: 論理プロセッサ数の半分と、空きメモリ ÷ 3GB の小さいほう（最低 1）まで。PC 全体の CPU 使用率が 90% 以上のときは取り込みを始めず（［読み込み］［船舶・車両をまとめて取り込む］も押せません）、下がるまで待ちます。待っている理由は進み具合の欄に出ます
  - 設定タブの「3D モデル」: **置き場所**（既定は Windows の TEMP の中の `StarCitizenJapaneseTextCreater\ship3d`。完全なパスだけ指定できます）、置き場所のドライブの容量（全体と残り）、**最大容量**（MB。初期値は置き場所のドライブの残り容量の 1/3、ただし最大 2GB。残り容量より小さい値だけ指定できます）、今の使用量。最大容量を超えたら、取り込みが終わるたびに古いものから消します（表示中・取り込み中・今取り込んだものは消しません）
  - ［船舶・車両をまとめて取り込む］: 保有している船（所持船と Hangar 同期の船）を先に、その後に［詳細］の船の一覧の残りを取り込みます。始める前に隻数・予想時間・予想サイズを出して確かめます。予想サイズの合計が最大容量を超える手前で止めます（まとめて取り込むでは古いものを消して入れ替えません。予想より大きくて少し超えることはあります）。最新のモデルがある船は飛ばします。欄の置き場所・最大容量を変えて［設定を保存］を押さずに［船舶・車両をまとめて取り込む］を押したときは、先にその値を反映して保存します
  - まとめて取り込むのボタン: ［船舶・車両をまとめて取り込む］は、前にまとめて取り込んだときの対象が、今のゲームデータ（Data.p4k）で全部取り込み済みなら押せません（横に「船舶・車両は今のパッチでは全部取り込み済み」と出ます）。パッチでゲームデータが変わると、また押せます。前の版のアプリで取り込んだ船があるときも押せます。ボタンにマウスを乗せると、今のゲームデータで取り込んだ数と取り込んでいない数が出ます（今のゲームデータでまとめて取り込んだ記録が無いときは、そう出ます）。設定タブの「3D モデルを保存しない」を入れると、船の 3D を見るたびにゲームデータから直接読み、置き場所には保存しません（既定は保存します。このときはまとめて取り込むは使えません）
  - パッチの後: Data.p4k が変わると、その船の元データ（Data.p4k の中のファイルの大きさと、Data.p4k に記録された CRC、船の構成）を書き出したときの記録と照合し、変わっていなければそのまま使います。変わっていた（照合できなかった）船のモデルは、消さずに裏で 1 隻ずつ取り直します（起動の 60 秒後と Data.p4k が変わったときに照合。CPU 使用率 90% 以上のときは待ちます。取り直すまでは古いモデルを出さず「自動の取り直しの順番待ち」と出し、［読み込み］を押すとその船を先にします。取り直せなかった船（ゲームから消えた船など）は消します）。照合中は「照合中」と出ます
  - アプリは、自分で書いた印のあるファイルだけを扱います（置き場所にほかのファイルがあっても消したり数えたりしません。同じ名前のほかのファイルがあるときは取り込みません）
  - 取り込みのログ: 船の 3D モデルの取り込みでは、作業フォルダの app_log.txt に詳しい記録を出します（待ち行列の順番・段階ごとの時間。取り消し・失敗のときは、そのときの段階と経過時間）
  - 子の乗り物の中身とリフトの台: 取り付けられた子の乗り物の中身（例: Drake Ironclad の操縦席のある Command Module の床・壁・キャノピー）と、リフト・エレベーターのかご（台）も、船の 3D に出ます。前の版で取り込んだ船は、取り込み直さずに、足りない区画だけを 1 回取り出して重ねて出します
  - 船内を歩く: ［船内］にすると、左上の 2 段目に［歩くモード］［走る］［姿勢］［すり抜け］のボタンが出ます（［詳細］の下の欄でも別ウィンドウでも同じ。武器・装備の 3D には出ません）。［歩くモード］を押すと床に立ち（座席にいるときは、その座席の降りる所の床から）、ステーションの 3D の歩くモードと同じ動きで、床・壁・天井に当たりながら歩けます（歩く・走る・ジャンプ・しゃがむ・寝そべる・はしご・すり抜け）。船のまわりには見えない床があり、船の外も歩けて、乗り込み用のはしごで船に入れます。エレベーター・リフトは、乗り場に近づくと行き先の窓が出て、選ぶとその階に移ります（かごと扉の形は動きません）。無重力・録画・コメントはありません（使い方は下の「[使い方 13. 船の 3D の塗装](#13-船の-3d-の塗装)」の「船内を歩く」）
- **マップ（星系図・現在位置・量子ジャンプ）** - ［マップ］タブに Stanton・Pyro・Nyx の星系図を出し、［現在位置］で取った座標や Game.log からの推定で、今いる場所と量子ジャンプの線を描きます
  - **自動で現在位置を取る**: 「QT・着陸・ゲーム開始のときに自動で現在位置を取る」をオンにすると、量子ジャンプの目的地を選んだとき（すぐ）・移動中になってから 15 秒後と 45 秒後・目的地を選んだ後に離陸してステーションや着陸場の区域を出てから 15 秒後と 45 秒後・着いたとき・2 回に分けて跳ぶときの 1 回目が終わったとき・着陸場に着いたとき・ゲームの世界に出たとき（読み込み画面が閉じたとき・復活したとき）に自動で取ります（初めはオフ。ゲームの窓が前にあり、mobiGlas が閉じているときだけ。目的地を選んだとき・着いたときなどは、前に自動で取り始めてから 10 秒以内は取りません。15 秒後と 45 秒後の分にはこの決まりを当てません。`/showlocation` を送って座標が返らなかったときは、送り直しません）
  - **契約のビーコン**: 契約のビーコンへ跳ぶときは、そのビーコンと組になっている契約の目標の印（無ければ量子ビーコンに限り選ぶ前 10 分以内の印）から、契約の目標（惑星・衛星の地表、ラグランジュ点の区域など）へ線を引きます（Yela を囲む小惑星帯などの決まらない印は「不明（契約のビーコン）」のまま）
  - **到着予定**: 目的地を選んでから到着するまでに座標を取ると、「（到着予定 18:06:00 頃・推定）」を出します。乗っている船の初期の量子ドライブの性能（最高速と加速度）から、「加速 → 巡航 → 同じ加速度で減速」の式で出発してから進んだ距離から残り時間を出します。目的地を選んでから 20 秒以内に取った点（出発の点）があれば、跳んだ後の点 1 つで出せます。出発の点が無ければ、目的地に近づいた点が 2 つ要ります。実測の巡航の速さがドライブの値と 5% 以上違えば、実測の速さで計算します。船やドライブが分からないときは、出発の点と加速中の 2 点から出します。計算の結果が有り得ない時刻（最新の点を取った時刻より前や、最新の点から「残りの距離をドライブの速さ（分からなければ実測の最も速い速さ）の 1/10 で進む時間」と「その速さに達するまでの時間の 10 倍」を足したものより後）になったときは「（到着予定を出せません: 理由）」と出します
  - **2 回に分けて跳ぶとき**: 地表の場所へ 2 回に分けて跳ぶときは「途中で 1 回止まります」を添え、1 回目が終わると「区間 1 の終わり（もう一度 QT が必要）」と出します
  - **途中で停止**: 移動中に目的地とは別の区域に入って 15 秒たっても戻らないときは「途中で停止（もう一度 QT が必要）」と出します。ただし、到着予定の時刻を 15 秒過ぎるまでの間と、区域が変わった後に取った続きの 2 点で目的地までの距離が 1 Mm 以上縮んでいて新しいほうの点が 30 秒以内に取ったものであるときは、停止にせず「移動中」のままにします
  - **施設のアイコン・施設で探す**: 星系図の場所の名札の横に、精製所・乗り物サービス・積載ドックのアイコンを出します。「場所」の検索の横で施設を選ぶと、その施設のある場所だけを探せます。アイコンはゲームのものを、各自の Data.p4k から取り出して使います（アプリには入っていません。取り出すまでは文字で出します）
  - **現在位置の近く**: 「現在位置の近く」の一覧は、同じ名前・同じ種類の近い場所は 1 行にまとめて「×2」、親と子が同じ所にあるもの（Seraphim Station と Seraphim Clinic、Orison と Orison General など）は親の行にまとめ、▼ を開くと子が出ます。場所の［詳細］の【距離】の表も同じです（図は下の「[使い方 14. マップの現在位置の近く](#14-マップの現在位置の近く)」）
  - **現在位置のキー**: ［現在位置］ボタンと同じ処理を、キーで動かせます（既定は 右 Shift + 左 Alt + Insert。Ctrl・Shift・Alt は左右を区別します）。ゲームの窓が前にあるままで取れ、アプリの窓は前に出ません。押したキーは、ゲームにもほかのアプリにもそのまま届きます（アプリが取り上げません）。決めていない修飾キー（既定のときの Ctrl など）を一緒に押していると動きません。設定タブの「現在位置のキーとオーバーレイ」でキーを変えられ、使わないようにもできます
  - **今いる場所で採掘できる物のオーバーレイ**: ［マップ］の［現在位置］ボタン・現在位置のキー・ステーションの 3D の［現在位置］で座標が取れたときに、今いる場所（ガス雲・小惑星の集まりの中、近くの惑星・衛星、小惑星の場所、小惑星帯）で採掘できる物を、ゲームの画面の上に重ねて出します（既定はオフ）。掘り方（船・ROC・手）ごとに、岩・格・出やすさ・シグネチャー・岩の中の資源と割合・倍率を、その下に資源ごとの品質の範囲とばらつきを出します。表示する秒数を決められます（既定 10 秒、0 なら出したまま）。文字の大きさ・透明度・位置・大きさは、設定タブの「現在位置のキーとオーバーレイ」で決めます（［オーバーレイを表示して調整］で出したまま調整でき、変えるとすぐ反映して保存します）。文字は決めた大きさで出て、中身が窓に収まらないときだけ、切れないように縮めます。ふだんはクリックがゲームへ通り、左 Ctrl + 左 Shift + クリックでも位置と大きさを変えられます（図と使い方は下の「[使い方 14. マップの現在位置の近く](#14-マップの現在位置の近く)」）

- **ステーションの 3D** - ステーション・都市の地図を、ゲームの部品をそのまま描く 3D で出します（図と使い方は下の「[使い方 12. ステーションの 3D](#12-ステーションの-3d)」）
  - **※ 一部の床に穴がある場合があります。粗い形で抜けていた床（例: Orison のトラムの乗り場の階段の前）は補っていますが、ほかの理由の穴が残っているかもしれません。歩くモードでは、そこで落ちることがあります（すり抜けモードにするか、いちばん低い床で止まる決まりで対処しています）。ステーションなどの 3D は、まだ十分ではありません。参考としてお使いください**
  - **※ 残っていること: ハンガーの中での現在位置は、まだ出ません。建物の区画の中の点をハンガーの所と判定することがある場所があります（Distribution Centre など。そのときは［本体のこの位置を見る］で戻れます）。Levski の一部の店（Wear & Tear、Hats & More、Tools & Supplies、Teach's など）は、販売品が出ません。Orison の一部の看板は出ません（ゲームの指定どおりの材質に差し替えると、デカールとして扱われるため）。色の入れ替えの向きは、実際のデータからの推定です**
  - 出し方: 別ウィンドウが開いていればそこに、無ければ［マップ］タブに出します（［別ウィンドウ］のボタンで別ウィンドウ）。［マップ］タブでは、星系図で拡大し切るとその場所の 3D に入り、3D で引き切ると星系図に戻ります。［詳細］タブのステーション・都市・前哨基地・小惑星の欄の［3D 表示］、契約の「■ 地図」のリンクからも開けます。場所を開いた直後は、外から引いた位置から始まります
  - 開く場所: 星系図で、行き先（端末・店・乗り場・ハンガーなど）が 1 つも無い場所（ラグランジュ点 HUR L5 など）を押すと、その場所の範囲の中の、行き先のあるいちばん近い場所（HUR-L5 High Course Station など）を開き、状態の欄に知らせが出ます（範囲の中にステーションの無い場所は、その場所のまま）。ステーションの中の小さな場所（クリニック・都市の病院など）を開くと、親のステーションの 3D を、その場所の店へ飛んだ形で開きます
  - 取り込み: 前もって大きなデータを作りません。開いたときに、見る所のまわりの区画だけをゲームデータ（選択中のチャンネルの Data.p4k）から取り出して描きます。区画の置き方の一覧（view3d_layout.db）はアプリに同梱していて、パッチで合わなくなったら裏で作り直します。設定タブの［マップをまとめて取り込む］は、この区画の置き方の一覧を作り直すボタンです
  - 速さ: 取り出した区画と計算した結果をディスクに保存して、次からは速く出します。空いているときは近くの行き先を先に読みます。設定タブの「ステーション (GB)」で上限を決めます（0 で保存しない）
  - 読み直しとメモリ: 引いて全体を見ている間は読み直しません。取り出し中・作画中の表示は、右下の小さな形で出します。3D を閉じたとき・星系図に戻ったときに、メモリを返します。歩くモードの当たり判定は、読み込んだ範囲の全部について前もっては作らず、歩いて近づいた所の升だけを作ります
  - トラムのある場所（Orison・Lorville・Area18・New Babbage・GrimHEX・Levski・Orbituary など）を開いたとき、その場所の中の現在位置が取ってあれば、現在位置のまわりだけを読み込んで、そこから始まります（まだ何も操作していないとき）
  - 床の穴: ゲームの粗い形（LOD1）で抜けていた建物の床（幅 50 cm〜10 m の穴）を、細かい形（LOD0）から補います（区画の置き方の一覧 view3d_layout.db に場所ごとに入れて同梱。パッチで形が変わった場所だけ裏で作り直します）。Orison のトラム乗り場の階段の下の床（幅 10 m 以上の平らな床）も補います
  - 歩くモードの補い: 歩いているとき、まわり 10 m・足元 ±50 cm の範囲で粗い形に物体が無い所があれば、裏でその部品の細かい形を読んで、そこにある物体（床の代わりになる照明・パネル・チューブなども）を足します。足した物体は描かれ、当たり判定にも入ります。見つけた物体は 3D の置き場所の view3d_fill_walk.db に入れ、次に開くときから最初から入ります（同じ形の部品すべてに効きます）
  - テクスチャ: ゲームのテクスチャを貼ります（端末・ポスター・看板・壁・床。画像は利用者の Data.p4k から取り出して 3D の置き場所に保存し、2 回目からは使い回します）。設定タブの「ステーションのテクスチャ (px)」で画像の大きさを決めます（既定 512、0 で貼らない）。右上の「テクスチャ」を切ると灰色の単色です
  - 場所ごとの色: ゲームのデータにある場所・部品ごとの色（パレット）を付けます。部品ごとの材質の差し替え（例: Orison の木の葉、看板）も入れます。ガラスは、色の付いたガラスはその色、色の無いガラスは薄い水色です。右上の「色付け」で切れます（切ると色の違いで分かれる材質が減り、描く回数が減ります。性能の低い PC 向け。どの場所でも共通の 1 つの状態。切り替えると今の地点を読み直します。「テクスチャ」を切っている間は押せません）
  - フロアと無重力: フロアの切り替えは、床から 2 m より上を消し、ほかの階は薄く出します（どちらも値を変えられます）。Onyx Facility などの無重力の場所・上下が逆の通路にも対応しています（歩くモードで浮く・逆さに立つ）
  - 左の欄: まとまりごとに区切ってあり、見出しの ▼ で畳めます（飛ぶ先／読み込み／歩くモード／録画／文字の道案内／フロア／店の入口／表示する形／操作の説明。初めは、飛ぶ先・歩くモード・文字の道案内が開いています。畳んだ状態は覚えます）。文字の道案内は、ドロップダウンで選んだ 1 つだけを出します（飛ぶ先で押した先があれば合わせます。部品の名前などの細かい部分は、設定「マップのデバッグ表示」がオンのときだけ）。操作の説明は、操作ごとに 1 行の表と、▼ くわしい説明です
  - 飛ぶ先の一覧: 店・端末・admin・薬局・クリニック・再生端末・エレベーター・トラム・階段・ハンガー・ハンガーロビー（ハンガーへ行くエレベーターのロビー側の乗り場。「ハンガーロビー: ロビー ×6」の形。乗り場の名前が違う一部の場所には入りません）・クエストの扉やカード・パネル、罰金の支払い端末。名前は日本語で出します。選ぶと文字の道案内（いちばん近い乗り口など）を出します
  - 飛ぶ先で店を選んだとき: 端末があれば端末の前、無ければカウンターの前（客側）、どちらも無ければ店の位置に立ちます
  - 右上のスイッチ: 3D の右上に、スイッチが縦に並びます。上から「テクスチャ」「色付け」「現在位置」、見出し「印」（店・端末・エレベーター・トラム・クエストの扉・パネル・コメント）、見出し「キャプション」（着陸パッド・ドッキングポート・外部貨物エレベーター・ハンガー。それぞれ色の丸と数）。切り替えた状態は覚えていて、次に開いたときもその状態です。外から引いて全体を見ているときは「印」が押せなくなり「キャプション」が押せます。中で見ているときはその逆です
  - 札: 自分からの距離を出します。店は「店名（種類）」で出し、端末の無い店にも札を出します（長い名前は種類だけ）
  - 外から見たとき: 店・端末などの中の印と札、コメントの印、重力の範囲の箱を出しません（近づく・中に入ると出ます）。着陸パッド（Pad01 など番号つき）・ドッキングポート（番号つき）・外部貨物エレベーター（見出し「外部貨物EV」）・ハンガー（大きさ S・M・L・XL でまとめ）の引き出し線と見出しを出します（AI 専用のものは出しません）。ハンガーの印は屋根の扉の上に来ます
  - ［現在位置］: ゲームの /showlocation の位置に移ります
  - 現在位置の印: 3D に現在位置の印（水色の玉と、札「現在位置 時:分:秒」）を出します。外から見ているときも消えません。右上の「現在位置」で切れます。自転する場所では、ずれることがある旨が札に出ます。読み込んだ範囲の外にあるときは出ません。［マップ］タブの自動の取得で取った現在位置も、その場所の 3D を開いていれば印が出ます（見ている所は動きません）。［マップ］タブの［現在位置］ボタンで取れたとき、または星系図の現在位置の印・その文字・右の欄の「現在地: …」の文を押したとき（位置は取り直しません）は、ステーションなど建物の中（現在地が「〜 内」）でその場所の 3D があれば、その場所の 3D に切り替わり、歩くモードで現在位置の所に立ちます（ハンガーの所ならそのハンガーを開きます。建物の中でないとき・3D の無い場所では星系図のまま。出す先は、別ウィンドウが開いていればそこ、無ければ［マップ］タブ）
  - 現在位置がハンガーの所のとき: 3D の［現在位置］は、そのハンガー（その入口の大きさ）の 3D を開きます。自動の取得で取ったときは、勝手には開かず、知らせ「ハンガー（S）の所にいます…」と、［ハンガー（S）を開く］［本体のこの位置を見る］が出ます。ハンガーの中での位置は、まだ出ません（エレベーターの乗り場の前に立ちます）。［マップ］タブの現在地の文にも「・ハンガー（S）」が付きます
  - 自転する星のまわりの場所での位置は、その前に取った補正を使って直します
  - 歩くモード: WASD で歩き、走る・ジャンプ・よじ登り・はしご・しゃがむ・寝そべる・すり抜けができます。エレベーターとトラムは、パネルや乗り口で行き先の一覧を出して移ります。マイハンガー（S・M・L・XL）の中も 3D で見られます。歩いた道の録画・再生と、コメント（ゲーム内の手順を残せます）があります
  - 歩くモードのコメント: Enter のコメントは録画中でなくても付けられ、決めた瞬間に印が出ます。印は 3D の置き場所の view3d_notes.db に保存し、次に開いても出ます（印を押すと消せます）
  - 歩くモードの手すり: 階段の手すりには乗りません（0.35 m を超える段差は、面の真下との差が 0.6 m を超える「手すりの高さ」なら上がりません）。横の当たりには縦の線もあり、細いバーをすり抜けません
  - エレベーター: 同じ高さにある別の行き先（Seraphim の貨物センターなど）も一覧に出ます。降りる側は扉の向きで決め、降りたら、行き先の扉の外の床の側で、扉に背を向けて立ちます
  - ハンガーのエレベーター: Lorville・New Babbage・Area18・GrimHEX のハンガー行きのエレベーターでも「マイハンガー（S・M・L・XL）」が出ます。マイハンガーの中のエレベーターの窓に、入るときに乗った路線の行き先（ロビー・着陸パッド・ドッキングポートなど）と、ほかの大きさのマイハンガー、「ステーションへ戻る」が出ます。操作盤・黄色の玉を押すと窓が開きます。データの無い大きさは出ません
  - シャトル・トラムの乗り場: 10 m 以内で行き先の窓が出ます
  - 右ドラッグ: 見るときの右ドラッグ・Shift＋左ドラッグは、マウスを上へ動かすと、見ている所が下へ動きます。歩くモードの右ドラッグは、上下の向きが左ドラッグと逆です
  - 店: 店の端末を押すと、販売品と値段を出します。枠はホイールでスクロールでき、見出しと ✕ は上に残ります
  - 店の販売品の枠: 品名の一部で絞り込む欄、表示する種類のチェック（種類ごとの数、［全部］で戻す。外した種類は次も同じ）、並び替え（元の順・品名・価格・種類、昇順・降順。次も同じ）があります
  - 3D の表示には同梱の three.js を使い、ネットからは読みません。ゲームの形・画像は配布せず、利用者の Data.p4k から取り出して使います
- **武器・装備の 3D** - ［詳細］タブで武器・装備（船の武器・部品、個人の武器、アーマー、ヘルメットなど）を開くと、名前のすぐ右に斜めの小さな絵が出て、押すと下の欄に 3D が出ます（回す・拡大縮小。品では船外／船内の切り替えを出しません。3D の右上の赤い ✕ で閉じます）。アーマー（胴・腕・脚）・アンダースーツ・服（シャツ・上着・ズボン・靴・帽子・手袋）は、置いたときの箱ではなく品の形で出ます。小さい品（手りゅう弾・マガジンなど）は、枠に合わせて大きく出ます。形の無い品は「形がありません」と出ます。テクスチャの無い白い面は灰色で出します
- **設定「マップのデバッグ表示」** - 設定タブの「3D モデル」の欄、「ステーションのテクスチャ (px)」の行の右。既定はオフです。オフのときは、ステーションの 3D で形を押したときに下に出る細かい文（部品の名前・判定など）と、文字の道案内の細かい部分を出しません。［設定を保存］の後、次に 3D を開いたときから効きます
- **ゲームデータの取り出し** - ゲームデータの取り出しは、すべてアプリの中の処理で行います（StarBreaker は使いません。StarBreaker と同じ結果になることを確かめてあります）。取り出しの時間は、作者の PC での実測で、Orison の区画 40 個で 3.8 秒、船の 3D は Polaris で 約 10 秒です。前の版が置いた手元の starbreaker.exe は、船の 3D を取り直したときに消します
- **採掘のシグネチャー** - ［鉱石］タブで、スキャナーの RS の数字から、鉱石の種類・岩の数・格・その場所で出る割合を出します（数字 = 1 個の値 × 岩の数 は推定です）
- **［詳細］の施設・MAP** - 場所の【基本】の上に施設のアイコンを並べ、【基本】に精製所・乗り物サービス・積載ドックの「あり／なし」を出します（ゲームの施設の一覧に無くても、取り込んだ地図に精錬の端末・外の貨物エレベーターがあれば「あり（推測）」）。場所の【お店】や品物の「購入」の表の店名の右の［MAP］で、［マップ］タブにその店の位置を出します。名前で探したときの候補は、星図の親子（HUR L2 と HUR L2-A、ステーションとクリニックなど）を ▼ でまとめます
- **お店の表の作り直し** - 起動後に裏で星図の場所・店の表を作るとき、今の形で作れなかったとき（作業の空きが足りない・失敗・取り消し・0 行で前の形の表が残った）は、次の起動でまた作ります（ログに「[お店] … 次の起動でまた作ります」と出ます）
- **自動更新** - 起動したとき（画面が出て 20 秒後）と毎日の時刻（既定 08:00）に新しい版を確かめ、新しい版があれば右下の窓で知らせます。［終了して更新］で、変わったファイルだけを取って入れ替えます（作業フォルダの DB と個人データには触りません）。設定タブの「自動更新」で入切・時刻を決められ、［更新を確認］でいつでも確かめられます
  - **データベースだけの更新**: アプリの版が同じままでも、配っているデータベース（翻訳・ゲームデータ・装備の購入場所・ステーションの 3D）が新しくなると、「データベースの更新があります」の窓で知らせ、前の版からの差分で取ります（差分が使えないときは丸ごと）。入れた後は、翻訳タブの［日本語化］→［次へ］→［実行］でゲームに反映します
- **PC 間の同期** - 設定タブで共有フォルダを指定すると、個人のデータ（所持船・My Hangar・所持コンポーネント・所持個人装備・鉱石の在庫・売買と採掘の記録・ゲームログの記録・装備の構成・手動の訳と用語集・チャットの記憶）を書き出し、別の PC の書き出しに新しいものがあれば取り込みます。アプリの起動・ゲームの起動・ゲーム中 10 分ごと・ゲームの終了・アプリの終了のときに自動で行い、「今すぐ書き出す」「今すぐ取り込む」のボタンもあります。2 台で同時に遊んで別々に変えた場合は、古いほうの変更が消えます
- **バックアップ（エクスポート / インポート）** - 設定タブの「データベース」で、翻訳 DB・ナレッジなどのデータを ZIP に書き出し、読み込めます。インポートでは、ゲームやネットから取ったデータはバックアップの内容に置き換え、自分で登録したもの（手動の訳・用語集・記憶・所持船など）は今のものを残して、バックアップにだけあるものを足します
- **タブの並べ替え** - タブをドラッグで並べ替えられます。並び順と最後に見ていたタブを覚えます

### 🔰 翻訳だけ使うなら

翻訳だけ使うなら、簡単に使えます。翻訳済みのデータベースが初めから入れてあるので、翻訳タブの **[日本語化]** ボタンを押して、日本語にする範囲を選んで **[次へ]**（全部を日本語にするなら「全て翻訳」、14 種類の中からチェックで選ぶなら「一部翻訳」）、ゲーム内で表示される名前に便利なオプションを付けるか選んで **[実行]** ボタンを押すだけです。

### 📦 翻訳DBについて

アプリ本体に翻訳データベースが同梱されています。別途バックアップをインポートする必要はありません。

- **初回インストール**: ダウンロードして展開するだけで翻訳データが使えます
- **アプリ更新時**: 同梱DBが新しくなっていれば、起動時に同梱DBを元に作り直します。自分で入力したもの（手動・CSV・用語集で入れた訳、用語集、チャットの記憶）は今のDBから引き継ぎます。ゲームやネットから取ったデータは同梱DBのものになります。作業フォルダのDBが空・壊れている・無いときも、起動時に同梱DBから作り直します
- **翻訳データをリセットしたい場合**: WorkDir 内の以下のファイルを削除してからアプリを起動してください。同梱DBがコピーされクリーンな状態になります
  - `translations.db` — 翻訳データ
  - `gamedata_cache.db` — ゲームデータインデックス（ミッション・船・アイテム等）
  - WorkDir の既定値は `C:\temp` です（設定タブで変更可能）

**新しい翻訳データベースが出たら、それを入れるだけで済みます。** 新しいパッチに対応した分の翻訳データベースが公開されたら、自分で [AI翻訳] をしなくても、アプリのバージョンアップを待たなくても、その更新を入れれば日本語が新しくなります。

- **自動更新で受け取る**: アプリの版が同じままでも、配っているデータベースが新しくなると、自動更新が「データベースの更新があります」の窓で知らせます。［終了して更新］を押すと、アプリが閉じ、データベースを入れ替えて、起動し直します
- **手で取り込む**: 上の `sc_japanese_backup.zip` をダウンロードし（展開はしません）、設定タブの「データベース」の [インポート (復元)] でその zip を選び、「翻訳データ」にチェックを入れて [インポート] を押します
- どちらも、その後に翻訳タブで [日本語化] → [次へ] → [実行] を行うと、ゲームに反映されます（ゲームには自動で書きません）
- 手で直した訳・CSV で入れた訳・用語集は残ります。自分で [AI翻訳] した行と、[全て原文] にした行は、配ったデータベースの内容に替わります
- 詳しくは **[使い方マニュアルの「新しい翻訳データベースが出たら」](https://batake321.github.io/StarCitizenJapaneseTextCreater/#translate-newdb)**

### 前の版から更新するとき

- **v2.1.1 以前からは、手で入れてください。** 自動更新で入れられるのは、v2.1.2 以降から上げるときです
- **v2.6.2 以前から更新したとき**: 初めて起動したとき、ゲームデータの読み直しが 1 回走ります（数分〜10 分ほど）。ステーションの 3D の地点は取り出し直しになります（保存済みの地点は使い回しません）
- **v2.5.x 以前から更新したとき**: 前の版で取り込んだ 2D のステーションの地図・古い方式のステーションの 3D のファイルは、起動の後に自動で消します
- **PC 間の同期を使っている方は、どちらの PC も v2.1.0 以降にしてください**（それより前の版の PC からも品質は消えないようにしてありますが、それより前の版のバックアップの書き出しは `-wal` の中身を入れません）
- **v2.0.11 以前から更新したとき**: 更新後に［装備データを再抽出］を 1 回実行してください

> 版ごとの更新内容は、この README の最後の「[更新内容](#更新内容)」にあります。

### 1. 翻訳タブ

![翻訳タブ](image/translate-tab.png)

1. **GamePath** が正しいことを確認（自動検出済み）。チャンネル (PTU/LIVE) を選択

4. Star Citizen を起動すれば日本語テキストが適用されます

![「日本語化の適応範囲」の窓](image/scope-dialog-num.png)

*「一部翻訳」を選び、チェックをいくつか外した例です。番号は下の表。*

| 番号 | ところ | すること |
|---|---|---|
| ① | **全て翻訳** / **一部翻訳** | 全て翻訳は全部を日本語にします（このときチェックは押せません）。一部翻訳にすると、下のチェックで種類を選べます。初めは全て翻訳です |
| ② | 種類のチェック（14 個） | チェックを付けた種類を日本語にします（外した種類は英語のまま）。品の名前／品の説明／コモディティの名前／コモディティの説明／船の説明／契約名／契約の説明／地名／契約の中の場所・品／人名・肩書き／台詞・字幕／画面の文字／派閥名／その他。初めは全部にチェックが付いています |
| ③ | **[次へ]** | 名前に付ける印を選ぶ窓（「日本語化」の窓）へ進みます |
| 次の窓 | 「日本語化」の窓 | 装備名の分類・契約名の派閥と貢献度・設計図の印を選びます |
| 次の窓 | **[実行]** | 選んだ範囲と印で、ゲームに書き出します。選んだ範囲は印と一緒に覚え、次も同じ状態で開きます |

- 外した種類は、ゲームの中で英語の原文のままになります。名前に付ける印（[軍1C] など）は、名前を英語のままにしても付きます
- 変わるのはゲームに書き出す global.ini だけです。アプリの画面の表示は変わりません

ゲームにパッチが来たら **[新しいパッチを読み取る]**（ゲームの版が読めたときは、ボタンに「4.10.2 LIVE を読み取る」のように版とチャンネルが出ます。新しい版があるときはボタンが黄色になります）→ **[日本語化]**。未翻訳を自分で訳すときは間に **[AI翻訳]** を挟みます。ログは「ログ」タブで見られます。

### 9. Web チャット — ブラウザ・スマホから利用

![Web チャット](image/web-chat.png)

PC のブラウザやスマホから、AI チャットと VoiceVox 音声読み上げを利用できます。

#### 起動方法

1. **設定** タブで HTTP ポート (デフォルト: `8099`) と HTTPS ポート (デフォルト: `8100`) を確認
2. **[サーバー起動]** をクリック — HTTP と HTTPS が同時に起動します
3. 初回のみ **UAC プロンプト** が表示されます — **はい** をクリック (Windows ファイアウォールの開放とポート登録を自動で行います)
4. 以下の URL にアクセス:
   - **PC**: `http://localhost:8099/`
   - **LAN (他のデバイス)**: `http://192.168.x.x:8099/` (アプリに表示される URL)
   - **HTTPS PC**: `https://localhost:8100/`
   - **HTTPS LAN (マイク利用)**: `https://192.168.x.x:8100/` (スマホのマイクにはこちらが必要)

> **`192.168.x.x` の確認方法:** PC でコマンドプロンプトまたは PowerShell を開き `ipconfig` を実行します。「Wi-Fi」または「イーサネット」の **IPv4 アドレス** (例: `192.168.1.15`) がこの PC のアドレスです。スマホから同じ Wi-Fi に接続し、そのアドレスでアクセスしてください。

#### VoiceVox 音声読み上げ

- [VoiceVox](https://voicevox.hiroshiba.jp/) をローカルで起動しておく必要があります（無料）
- 入力欄の右の **スピーカーのボタン**（送信ボタンの左）を押すと音声読み上げが **ON** になり、ボタンが緑になります（押さなければ読み上げません）
- ON の状態では: 質問送信時に「おまちください」、回答時に「お待たせしました」+ AI が生成した要約を読み上げ
- 画面右上の歯車アイコンから話者 (キャラクター) を変更可能

#### スマホからの利用方法

スマホと PC が同じ Wi-Fi に接続されていれば、スマホのブラウザからチャットを利用できます。

**マイク (音声入力) を使わない場合:**

スマホのブラウザで `http://192.168.x.x:8099/` にアクセスするだけで利用できます。

**マイク (音声入力) を使う場合:**

Chrome はセキュリティ上、`localhost` 以外の HTTP ではマイクを許可しません。HTTPS が必要です。

1. アプリの **[サーバー起動]** をクリック — HTTP (8099) と HTTPS (8100) が同時に起動します
2. 初回のみ Windows の **UAC プロンプト** (管理者権限) が表示されます — **はい** をクリック (証明書のインストール、HTTPS ポートの登録、ファイアウォールの開放に必要)
3. 初回のみ Windows の **証明書インストール確認** が3回表示されます — すべて **はい** をクリック (自己署名証明書を PC の信頼済みストアに登録)
4. スマホのブラウザで `http://192.168.x.x:8099/cert` にアクセス
5. **[証明書をダウンロード]** をタップしてインストール:
   - **iPhone**: 設定 → 一般 → VPN とデバイス管理 → プロファイルをインストール → 設定 → 一般 → 情報 → 証明書信頼設定 → 有効化
   - **Android**: 設定 → セキュリティ → 証明書のインストール → CA 証明書 → ダウンロードしたファイルを選択
6. `https://192.168.x.x:8100/` にアクセス — マイクが使えるようになります

⚠️ **「この接続ではプライバシーが保護されません」と表示された場合:**

自己署名証明書を使用しているため、ブラウザが警告を表示することがあります。これは正常です。

- **PC (Chrome)**: **[詳細情報を表示しない]** をクリック → **[192.168.x.x にアクセスする（安全ではありません）]** をクリック
- **iPhone (Safari)**: **[詳細を表示]** → **[この Web サイトを閲覧]** をタップ
- **Android (Chrome)**: **[詳細設定]** → **[192.168.x.x にアクセスする（安全ではありません）]** をタップ

この警告は自宅 LAN 内の自己署名証明書によるものであり、通信自体は暗号化されています。一度アクセスを許可すれば、同じブラウザでは次回以降表示されません。

#### マイクが使えない場合 (Q&A)

**Q. マイクボタンを押しても反応しない / 「マイクの許可が必要です」と出る**

A. Chrome はセキュリティ上、`localhost` 以外では HTTPS 接続でないとマイクを許可しません。`https://192.168.x.x:8100/` でアクセスしてください (`http://` ではなく `https://`、ポートは `8100`)。

**Q. HTTPS でアクセスしてもマイクが使えない**

A. Chrome のアドレスバー左の鍵アイコン (または ⚠️ アイコン) をクリック → **マイク** の項目を確認してください。
- トグルが **OFF** になっている → **ON** に切り替え
- 「サイトアクセス時は常に許可」にチェックを入れると、次回以降の確認が不要になります
- 使用するマイクデバイスもここで選択できます

**Q. 「このサイトへの接続は保護されていません」と表示されるが問題ないか？**

A. 自己署名証明書を使っているため Chrome が警告を表示しますが、自宅 LAN 内の通信は暗号化されており問題ありません。マイクの利用には影響しません。

**Q. ゲーム用ヘッドセットなど、別のマイクを使いたい**

A. Chrome はデフォルトのマイクデバイスを使用します。切り替えるには:
1. アドレスバー左のアイコン (🔒 または ⚠️) をクリック
2. **マイク** の項目をクリック
3. ドロップダウンから使いたいマイクデバイスを選択
4. **「サイトアクセス時は常に許可」** にチェックを入れると次回以降の確認が不要になります

**Q. スマホでマイクが使えない**

A. 以下を確認してください:
1. `https://` でアクセスしているか (ポートは HTTPS 用の `8100`)
2. 証明書をスマホにインストール済みか (`http://192.168.x.x:8099/cert` からダウンロード)
3. ブラウザのマイク許可を求めるポップアップで **許可** を選択したか
4. スマホの設定 → アプリ → Chrome (または Safari) → マイクが有効か

> 証明書はこの PC 専用の自己署名証明書です。外部の認証局は使用しません。不要になったらスマホから削除してください。
>
> ファイアウォールは「SC Japanese Assistant HTTP」「SC Japanese Assistant HTTPS」というルール名で自動登録されます。アンインストール時は Windows Defender ファイアウォール → 受信の規則 から手動で削除してください。

#### データ API (読み取り専用)

> **Web チャットサーバーを起動していないと、データ API は使えません。** **設定** タブの **[サーバー起動]** を押してから呼んでください。アプリを起動したときに自動で起動させるには **[自動起動]** にチェックを入れます。

Web サーバーを起動している間は、詳細タブ・交易・契約などのデータを JSON か HTML で読み出せます。ほかのツールやスクリプトから使うためのもので、**すべて GET の読み取り専用**です (DB には書き込みません)。データは画面と同じ読み方で出します。

- **ポート**: Web チャットと同じです。`http://localhost:8099/api/…`、HTTPS なら `https://localhost:8100/api/…` (LAN の他の機械からは `192.168.x.x`)
- **形式**: `format=json` (既定) か `format=html`。それ以外は 400 になります
  - JSON の**一覧**は `{ "total": 全体の件数, "count": 返した件数, "items": [ … ] }` です。`total` は `limit`・`offset` を通す前の件数、`count` は返した件数です
  - JSON の**詳細**は `{ "record", "name", "text" }` です。項目はアプリの中のデータの項目名のままです
  - HTML の一覧は表、詳細は詳細タブと同じ見た目のページです。詳細の中のリンクは `/api/detail?record=…&format=html` に移ります
- **件数**: 一覧には `limit` (最大件数。1 以上の整数) と `offset` (飛ばす件数。0 以上の整数) を付けられます。付けなければ全件です。`/api/search` の `limit` だけは 1〜1000 です
- **生の JSON**: 契約の一覧の `RawJson` (ゲームデータの生の JSON。とても大きい) は、既定では出しません。`raw=1` を付けたときだけ出します
- **個人のデータ** (パスが `/api/my/` で始まるもの) は **この PC から**呼んだときだけ返します。要求元がこの PC (ループバック) で、しかも `Host` ヘッダーのホスト名が `localhost`・`127.0.0.1`・`[::1]` のどれか (ポートは問わない) のときだけです。それ以外は 403 になります。個人のデータの応答には CORS のヘッダーを付けません
- **ゲームのデータのルートに混ざる個人のデータ** (`/api/blueprints` の所持 `Owned`・在庫 `StockText` `stockText`・手持ち `haves`、`/api/detail` と `/api/missions/detail` の【ブループリント】の節の「在庫」「所持」の行と「手持ち」の欄) も、`/api/my/` と同じ条件 (この PC から、`Host` が `localhost`・`127.0.0.1`・`[::1]`) のときだけ画面と同じに出し、そのときの応答には CORS のヘッダーを付けません。条件に合わない要求 (LAN の他の機械から・`Host` が違う) には、個人のデータを出さずに CORS のヘッダーを付けて返します。ほかのゲームのデータのルートは、いつも CORS のヘッダーを付けます
- **エラー**は形式にかかわらず `{ "error": "…" }` で返します。引数の誤りは 400、個人のデータをこの PC 以外から読もうとしたときは 403、見つからないとき・`/api/` で始まる知らないパスは 404、GET 以外は 405、データがまだ無いときは 503、アプリの中の失敗は 500 (`"内部エラー"`。中身はアプリのログ `app_log.txt` に残します)

| パス | 中身 | 応答の形 | 主な引数 |
|---|---|---|---|
| `/api` | API の一覧 | 一覧 (`path`・`description`・`parameters`・`personal`) と `formats` | |

### 11. 設定タブ — Web チャット・VoiceVox・データベース管理

![設定タブの上の部分](image/settings-top.png)

*設定タブの上の部分です。絵の「ゲームデータ連携 (Data.p4k)」の説明文は「StarBreaker CLI で…」ですが、今の版では「アプリの中の処理で…」です。*

1. **基本設定**: GamePath・Working Directory・Output Language を確認・変更
2. **ゲームデータ連携**: **[インデックス構築]** で Data.p4k からゲームデータを抽出・キャッシュ
3. **Web チャット**: HTTP ポート (8099) と HTTPS ポート (8100) を設定し **[サーバー起動]** でブラウザ/スマホからアクセス可能に
4. **VoiceVox URL**: VoiceVox の接続先 (デフォルト: `http://localhost:50021`)、話者 ID、速度 (0.5〜2.0 倍。Web チャットとゲームログの読み上げの両方) を設定
5. **データベース**:
   - **[エクスポート (バックアップ)]** — 翻訳 DB・ナレッジを含む全データを ZIP で保存
   - **[インポート (復元)]** — バックアップ ZIP を読み込み (翻訳データ・用語集・ゲームデータインデックス・記憶データ・交易データを選択可)
   - **個人データを含める** — エクスポートに、所持船などの個人データを入れるかを選びます
   - **[翻訳DBクリア (全翻訳データ削除)]** — 翻訳データを全部消します
6. **日本語フォント (gfx)**: 字が足りず □ になる漢字を出すため、ゲームの日本語フォント (fonts_en.gfx) を、字がすべて入ったもの (Noto Sans JP) に置き換えます
   - **[フォントを置く]** — 最新の公開物 (GitHub のリリースの添付 `fonts_en.gfx`) を取り、大きさと SHA-256 を確かめてから `<GamePath>\data\Localization\japanese_(japan)\UI\fonts\Shared\fonts_en.gfx` に置きます。効くのはゲームを起動し直してからです
   - Data.p4k の中の元のフォントが、このフォントを作ったときと変わっている（パッチで変わった）とき、または確かめられないときは、置く前に「それでも置きますか？」と聞きます
   - 置いたら、置いたファイルの SHA-256 を印のファイル `fonts_en.gfx.scjptc`（置き先と同じフォルダ）に書きます。置き先のファイルの SHA-256 が最新の公開物の記録か印の値と同じなら、このアプリが置いたものとみなして、控えを取らずに置き換えます
   - 置き先にこのアプリが置いたもの以外のファイルがあれば `fonts_en.gfx.bak` に移しておきます。`fonts_en.gfx.bak` がもうあるときは上書きせず、`fonts_en.gfx.bak.<yyyyMMddHHmmss>`（移した日時）に移して残します（［元に戻す］で戻すのは `fonts_en.gfx.bak` だけです）
   - **[元に戻す]** — 置いたフォントを「消しますか？」と聞いてから消し、印も消します（控えがあれば戻します）。このアプリが置いたものか確かめられないとき（公開物の記録とも印とも一致しない、またはネットにつながらず印も無い）は、そう書いた確認を出し、［はい］なら消します。控えが無ければ、消したあとゲームは Data.p4k の中の元のフォントを使います
   - ゲームの起動中は置けません（戻せません）。押したときと、置く（消す）直前の 2 回確かめます。Output Language が `japanese_(japan)` でないときは置きません
   - CIG が公式に認めているのは global.ini と user.cfg だけです。gfx の置き換えは認められたものではありません。**自己責任でお使いください**
7. **マップのデバッグ表示**: 「3D モデル」の欄の「ステーションのテクスチャ (px)」の行の右。既定はオフです。入れると、ステーションの 3D で形を押したときに、画面の下部に押した部品の名前・判定の面・押した所の高さなどの細かい文を出します（文字の道案内の細かい部分も、オンのときだけ出します）。［設定を保存］の後、次に 3D を開いたときから効きます
8. **船・装備・武器の 3D の色付け**: 「3D モデル」の欄の「3D モデルを保存しない」の右。既定はオンです。切ると、船・装備・武器の 3D をパレットの色を付けずに材質そのものの色で出し、塗装の一覧は出しません（取り込んだ 3D モデルは作り直しません）。ステーションの 3D の「色付け」スイッチとは別です。［設定を保存］の後、次に 3D を開いたときから効きます

   ![設定「マップのデバッグ表示」「船・装備・武器の 3D の色付け」（仮の図）](docs/img/v263-settings-debug.svg)

   *仮の図です。実際の画面と細部が違うことがあります。* ① マップのデバッグ表示のチェック（既定はオフ） ② 入れたときだけ、3D で形を押すと下部に出る細かい文 ③ 船・装備・武器の 3D の色付けのチェック（既定はオン）

- キー: W・S 前後／A・D 左右／Q・E・ドラッグ 向き／Shift 走る ON・OFF／スペース ジャンプ（前に上がれる段があれば、よじ登る）／C しゃがむ／Ctrl 寝そべる／N すり抜け ON・OFF／はしごのそばで W で上る・S で下りる／はしごの上でスペース 見ている向きの近くの床へ降りる
- 船の外: 船のまわりに見えない床があり、船の外も歩けます。［歩くモード］は［船内］のときに押します。自由な動きで船の外へ出てから押すと、外の見えない床に立って始まります
- はしご: 船内のはしご（階の間）は、ゲームのデータのはしごの位置と高さを使います（このデータは配るデータベースに入っていて、船の取り込み直しは要りません）。乗り込み用のはしご（例: Drake Ironclad の左右の側面と屋根のハッチ）は、3D モデルに入っている乗り降りの点から作り、地面（見えない床）から上って船内へ入れます
- エレベーター・リフト: 乗り場に近づく（水平 2 m 以内）と行き先の窓が出て、行き先を選ぶとその階に移ります（ステーションのエレベーターと同じ使い方です）。今の階の行か Esc で閉じます。着いた乗り場・閉じた乗り場では、3 m 離れるまで窓は出ません。かご・扉の形は動きません。乗り場と行き先は、ゲームのデータのものです（配るデータベースに入っていて、船の取り込み直しは要りません）
- 船内のドアは閉じた形のまま出ますが、歩いて抜けられます
- できないこと: エレベーター・リフトのかごと扉の形は動きません（乗り場で行き先を選んで移ります）。無重力・録画・コメントはありません。歩くモード中は、「船内の位置」・Home・ホイール・↑↓ は効きません

### 14. マップの現在位置の近く

［マップ］タブの【現在位置の近く】の一覧は、似たものを並べずにまとめます。場所の［詳細］の【距離】の表も同じまとめ方です。

![［マップ］タブ](image/map-tab.png)

*［マップ］タブです。右の欄が【現在位置の近く】で、▼ の付いた親の行と「×2」の行が出ています。*

![マップの現在位置の近くの一覧（仮の図）](docs/img/v263-map-near.svg)

*仮の図です。場所の名前・種類・距離・時刻は例です。実際の画面と細部が違うことがあります。*

| 番号 | ところ | 内容 |
|---|---|---|
| ① | 「・ハンガー（S）」 | 取った座標がその場所のハンガーの所のとき、現在地の文に付きます（自分のハンガーかどうかは見分けません） |
| ② | ▼ 親の行（N 件） | 親と子が同じ所にあるもの（Seraphim Station と Seraphim Clinic、Orison と Orison General など）を親の行にまとめます。押すと子の行が開きます |
| ③ | └ 子の行 | 開いたときに出ます（初めは隠れています） |
| ④ | ×2 | 同じ名前・同じ種類の近い場所を 1 行にまとめた数です |

- ［現在位置］ボタンで取れたとき、または星系図の現在位置の印・その文字・この欄の「現在地: …」の文を押したとき（位置は取り直しません）は、ステーションなど建物の中（現在地が「〜 内」）でその場所の 3D があれば、その場所の 3D に切り替わって現在位置の所を出します。自動の取得では、3D を新しく出しません（出ている 3D が今いる位置に合わなくなったときに、星系図に戻るだけです）。Game.log で着陸場に着いたとき（ゲームログの「到着」と同じとき）は、座標を取らなくても、着いたステーションの 3D を外から見た形で出します。建物の中でなくても、3D のあるステーションから 50 km 以内で、そのステーションから出てきた後でなければ、そのステーションの 3D を外から見た形で出します（着陸パッド・ハンガー・ドッキングポートの印が見えます）。どちらでもないときは星系図のままです（［マップ］タブに 3D が出ていれば、星系図に戻ります）

#### 現在位置のキー

［現在位置］ボタンと同じ処理を、キーで動かせます。**既定のキーは 右 Shift + 左 Alt + Insert** です。ゲームの窓が前にあるままで取れ、アプリの窓や 3D の別ウィンドウは前に出ません。

- Ctrl・Shift・Alt は左右を区別します（既定のキーは、右 Alt・右 Shift で押しても動きません）
- 押したキーは、ゲームにもほかのアプリにもそのまま届きます（アプリが取り上げません）。決めていない修飾キー（既定のときの Ctrl など）を一緒に押していると動きません
- キーを変える・使わない: 設定タブの「現在位置のキーとオーバーレイ」の「キーで現在位置を取る」のチェック（既定は入っています）と「キー:」の欄です。欄を選んで割り当てるキーを押し、**[設定を保存]** で有効になります
- 詳しくは **[使い方マニュアルの「現在位置のキー」](https://batake321.github.io/StarCitizenJapaneseTextCreater/#map-hotkey)**

#### 今いる場所で採掘できる物のオーバーレイ

［マップ］の［現在位置］ボタン・上のキー・ステーションの 3D の［現在位置］で座標が取れたときに、今いる場所（ガス雲・小惑星の集まりの中、近くの惑星・衛星、小惑星の場所、小惑星帯）で採掘できる物を、ゲームの画面の上に重ねて出せます。**既定はオフ**です。設定タブの「現在位置のキーとオーバーレイ」の「現在位置を取ったら、その場所で採掘できる物をゲームの画面に重ねて出す」にチェックを入れて、**[設定を保存]** を押すと出るようになります。

> **※ ゲームはボーダーレス（枠なしのウィンドウ）で使ってください。** 全画面の排他モードのゲームの上には、オーバーレイが出ないことがあります（確かめていません）。

![オーバーレイの中身](image/v264-overlay-content.png)

*オーバーレイの中身です（アプリの描いた絵で、ゲームの画面に重ねた所ではありません。背景の暗い色と明るい帯は、ゲームの画面の代わりに敷いた色です。場所は Yela の例）。*

| ところ | 内容 |
|---|---|
| 見出し | 場所の名前（星系）。例「Yela（Stanton）」 |
| 掘り方ごとの行 | 船で採掘・ROC で採掘・手で採掘 の順に、岩 1 つを 1 行で出します。列は 岩・格・出やすさ・シグネチャー・岩の中の資源と割合 です |
| 岩の中の資源と割合 | その岩に入っている資源と、割合の範囲です。「（倍率 0.49）」は、岩の中の行ごとの品質の倍率です（ゲームデータの値そのまま） |
| 品質 | 資源ごとの品質の範囲とばらつきです（例「501〜1000（ばらつき 150）」） |
| どの採掘の場所の中でもないとき | 「近くの採掘の場所」として、今いる位置から近い順に、QT できる採掘の場所を 3 か所まで出します（名前・距離・岩の名前）。1 か所も無ければ「ここで採掘できる物のデータはありません」と出ます |

- 「表示する秒数:」（既定 10）で、出してから消えるまでの秒数を決めます。0 なら出したままです。もう一度現在位置を取ると数え直します
- QT・着陸・ゲーム開始のときの自動の取得では出しません
- **位置・大きさ・文字の大きさ・透明度は、設定タブの「現在位置のキーとオーバーレイ」で決めます**（ゲームの中ではマウスがゲームに取られていて、オーバーレイを押せないためです）。文字の大きさ、透明度、位置（数値と ←→↑↓ のボタン）、大きさ（幅・高さの数値と ＋・− のボタン）があり、変えるとすぐ反映して、その場で保存します。［オーバーレイを表示して調整］を押すと、時間で消えずに出たままになり、マウスでそのまま動かせます（現在位置が無いときは見本の中身を出します）。［既定に戻す］で元に戻せます
- 文字は決めた大きさで出ます。中身が窓に収まらないときだけ、切れないように縮めます
- オーバーレイは、ふだんはクリックを下のゲームへ通します。**左 Ctrl + 左 Shift + クリック**でも変更中になり（黄色の枠・つまみ・右上の ✕ が出ます）、ドラッグで移動、端・角のドラッグで大きさを変え、動かさずにクリックすると確定します。✕ は確定せずに閉じます

![変更中のオーバーレイ](image/v264-overlay-edit.png)

*変更中のオーバーレイです（アプリの描いた絵で、ゲームの画面に重ねた所ではありません。場所は PYR3 L1 の例）。*

- 詳しくは **[使い方マニュアルの「今いる場所で採掘できる物のオーバーレイ」](https://batake321.github.io/StarCitizenJapaneseTextCreater/#map-overlay)**

## Ollama + Gemma4 の設定方法

ローカル LLM を使えば **API キー不要・無料** で翻訳できます。

**1. Ollama をインストール** ([詳細ガイド](docs/Ollama_Install.md))

[ollama.com](https://ollama.com/) からインストーラーをダウンロード・実行します。

**2. 翻訳用モデルをダウンロード**

```bash
# 高品質モデル (VRAM 4GB 以上推奨)
ollama pull gemma4:4b

# 軽量モデル (VRAM 2GB でも動作)
ollama pull gemma4:2b
```

> VRAM に余裕があれば `gemma4:26b` (高精度) や `gemma4:12b` (バランス型) も使えます。

**3. AI 設定ダイアログで設定**

| 項目 | 設定値 | 説明 |
|---|---|---|
| **Type** | `Ollama` | ドロップダウンから選択 |
| **Base URL** | `http://localhost:11434` | Ollama のアドレス (別 PC の場合は IP を変更) |
| **Model** | `gemma4:4b` or `gemma4:2b` | ダウンロードしたモデル名を入力 |
| **Batch** | `15` | 一度に送る翻訳数 (VRAM に応じて調整) |

**4. Ollama のコンテキスト長を増やす (重要)**

Ollama のデフォルトコンテキスト長 (2048 トークン) では、翻訳プロンプト＋固有名詞リストが収まりきらずパースエラーになる場合があります。以下のいずれかで対処してください:

- **方法 A: 環境変数で設定** — Ollama 起動前に `OLLAMA_NUM_CTX=8192` を設定
- **方法 B: Modelfile でカスタムモデルを作成**:

  ```bash
  ollama create gemma4-8k -f - <<EOF
  FROM gemma4:4b
  PARAMETER num_ctx 8192
  EOF
  ```

  作成後、AI 設定の Model に `gemma4-8k` を指定

> **翻訳がパースエラーで失敗する場合**: ログに「パース失敗 (0行)」と表示される場合、コンテキスト長不足が原因の可能性があります。上記の方法でコンテキスト長を 8192 以上に増やしてください。Batch を減らす (1〜5) ことでも改善する場合があります。
>
> **VRAM に関する注意**: Ollama (Gemma4) はGPUのVRAMを使用します。Star Citizen もVRAMを大量に消費するため、**ゲームプレイ中に翻訳やチャットを実行するとVRAMが圧迫され、ゲームのパフォーマンスが低下する場合があります**。ゲーム中の使用を避けるか、軽量モデル (`gemma4:2b`) を使用するか、別PCのOllamaに接続することを推奨します。Claude / Gemini などのクラウドAPIを使用する場合はVRAMへの影響はありません。
>
> **VRAM 使用量の確認方法:**
> - **NVIDIA**: タスクマネージャー → パフォーマンス → GPU → 「専用 GPU メモリ使用量」を確認。またはコマンドで `nvidia-smi` を実行
> - **AMD**: タスクマネージャー → パフォーマンス → GPU → 「専用 GPU メモリ使用量」を確認。またはコマンドで `rocm-smi` を実行 (ROCm インストール時)
> - Star Citizen 起動中は通常 6〜10GB の VRAM を使用します。`gemma4:2b` は約 2GB、`gemma4:4b` は約 4GB の VRAM を追加消費します
