# 作業内容: キーバインドエディターのコントローラー・HOTAS 入力対応（2026-10-13）

## 目的
キーバインドエディターで、コントローラーや HOTAS のボタンを押すと、今の割り当てが表示され、そのまま変更もできるようにする。保存するときは、今のファイルへの上書きと新規作成を選べるようにする。

## 経緯
1. 調査で次のことが分かった。
   - 実際の actionmaps.xml では js1 が VKBsim Gladiator EVO **L** なのに、アプリは js1 を R と決め打ちして表示していた。表示名も「NXT」と直書きだった。
   - 「保存」は actionmaps.xml を丸ごと作り直していた。そのため、デバイスの定義（`<options>`）などが消える作りだった。
2. Windows.Gaming.Input を使えば、パッケージを足さずに VKB 2 本を読めることを確かめた（VID 231D / PID 0201・0200）。
3. 利用者と仕様を決め、入力を読む部品を作り、画面に組み込んだ。

## 利用者が決めた仕様
- **HOTAS タブ・コントローラータブ**: ボタンを押すと、該当する行（またはボタンの図形）を強調し、スクロールする。編集画面は開かない。
- **バインディング編集**
  - 開いている間はずっと入力を待ち受ける。
  - 押すと確認欄が出る。中身は、押した入力、この機能の今の割り当て、その入力を使っている他の機能。ボタンは［反映］［キャンセル］。
- **左右の決め方**: actionmaps.xml の `<options type="joystick">` にある Product（VID/PID）から決める。取り違えたときは、次の 2 つの方法で直せる。
  - **表示の入れ替え**: アプリの中だけで入れ替える。設定は `<作業フォルダ>\keybind_hotas_display_swap.json` に保存フォルダごとに記録する。保存フォルダの中には置かない（フォルダ内の全ファイルがゲームへコピーされるため）。
  - **js1/js2 の入れ替え**: ファイルも書き換える。rebind の js1_ と js2_、options の instance 1 と 2 を交換する。片側の電源が遅れて、ゲーム起動時に左右が逆になったとき用。
- **保存**: ［上書き保存］［新規作成］［キャンセル］から選ぶ。
  - 上書き保存は、元のファイルの options などをそのまま残し、rebind の input だけを書き換える。
  - 新規作成は、元の保存フォルダを丸ごと複製してから書く。名前に空白（全角を含む）があれば拒否する。
- **修飾キー付きの値**: ゲームと同じ形（`js1_rctrl+button30`、`gp1_shoulderl+a`）にする。
  - 以前アプリが作っていた形（`kb1_rctrl+js1_button30`）は、読み込むときに直す。
- **js3 以降の値**: どの欄にも入れない。画面にも出さない。保存のときは、ファイル上のそのままにして触らない。XML 書き出しには入らないが、これは容認。
- **バインディング編集の修飾キー**: 編集中の機器に合わないものは選べないようにする。
  - パッドの編集中は、キーボードの修飾キーを使えない。
  - それ以外の機器の編集中は、LB/RB を使えない。
- **画面の表示は日本語**（左Shift、ボタン5、スペース、↑、テンキー0、英数 など）。
  - チャットで AI に渡す値は、従来の表記のまま。
  - チャットの「HOTAS R / L」は、実際の左右に合わせる。

## 変更したファイル
- `GameControllerInput.cs`（新規）: Windows.Gaming.Input で、ボタン・ハット・パッドの押した瞬間を通知する部品。
  - 読めないデバイスは、1 秒後に読み直す。
  - 止めている間に押したものは通知しない。
  - 処理の入れ子を防ぐ。
- `ActionMapModel.cs`
  - デバイスの定義を読み込む。
  - 左右の判定。
  - 値をゲームの形に直す（InputCodeHelper）。
  - js3 以降の振り分け。
  - 上書き保存の書き込み（SaveMergedOverrides）。何も変えずに保存すると、元のファイルとバイト単位で同じになる。
  - 画面用の日本語表示（FormatInputJa、*DisplayJa）。
- `KeybindEditorWindow.xaml` / `.xaml.cs`
  - 入力の待ち受けを始め、閉じたら破棄する。
  - 保存方法を選ぶ画面、上書き保存、新規作成。
  - 表示の入れ替えの設定を記録する。
  - CSV の見出しを HotasR(jsN) / HotasL(jsN) にする。
- `HotasLayoutPanel.xaml` / `.xaml.cs`
  - 左右と機種名を表示する。
  - 押した行を強調する。
  - 2 つの入れ替えボタン。
- `GamepadLayoutPanel.xaml.cs`: 押したボタンを強調する。
- `BindingEditDialog.xaml` / `.xaml.cs`
  - 押したときの確認欄。
  - 修飾キーを選べるかどうかの切り替え。
  - 左右の表記。
- `InputAssignDialog.xaml.cs`: 左右の表記、照合をゲームの形に合わせる。
- `KeyboardLayoutPanel.xaml` / `.xaml.cs`、`MouseLayoutPanel.xaml` / `.xaml.cs`、`KeyAssignDialog.xaml` / `.xaml.cs`: 表示を日本語にする。
- `ChatService.cs`: HOTAS の R/L を、実際の左右の対応で出す（2070〜2074 行目あたりだけ）。

## 確かめたこと
- ビルドは、エラー 0・警告 0。
- 保存処理は、保存フォルダの写しで試した。D:\temp\saves\controls の 5 つで試した。
  - 何も変えずに上書きすると、5 つすべてで元のファイルとバイト単位で同一だった。
  - js1/js2 を入れ替えると、既定の割り当ても js2 へ移った。js3 の rebind 183 行は変わらずに残った。
  - 修飾キー付きの値は、保存して開き直し、何も変えずにもう一度保存しても消えなかった。
- チャットに渡る従来の表記は、348 通りの入力で変更前と差 0 件だった。
- 実機の VKB 2 本が一覧に出ることを確かめた。
