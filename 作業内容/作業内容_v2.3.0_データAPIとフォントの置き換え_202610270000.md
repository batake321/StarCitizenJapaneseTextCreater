## データ API（v2.3.0 で公開）
- 場所: アプリ内 Web サーバー（ChatWebServer。既定 HTTP 8099・HTTPS 8100）。本体は ChatWebServer.DataApi.cs。
- 利用者が決めたこと:
  - アプリ内 Web サーバーに作る（GitHub Pages の JSON ではない）。データは船・装備・武器／交易・店・ターミナル／契約・鉱石・設計図・星図／個人のデータの全部。詳細画面で検索できるものは全部出す。
  - 出力は `format=json`（既定）/`format=html`。一覧は `{count,total,items}`、`limit`/`offset`。
  - 個人のデータはこの PC だけ（ループバック かつ Host が localhost・127.0.0.1・[::1]）。CORS は付けない。LAN からの要求では、BP の所持・在庫・手持ちも出さない。
  - GET で DB に書き込まない（HangarService・OreService に読み取り専用版を足した。重複のまとめはメモリ上で既存の Merge と同じ計算）。
  - 画面側の private（BlueprintPanel.LoadData、MakeLoadoutRow、ParseSuffixedNumber など）を internal にして全部出す。CommodityLabel は Dispatcher.Invoke で渡す。
  - 詳細の HTML の表の行に入った生の HTML を打ち消す（アプリの詳細画面にも効く）。
- 親が決めた細部: 契約の RawJson は `raw=1` のときだけ。500 は「内部エラー」だけ返して app_log.txt に記録。ShopTree・MissionService は DB の印が変わるまで使い回す。/api/ の知らないパスは 404 と {error}。
- 検証: 最終検証で「漏れる・消える・壊れる・落ちる」は 0 件。ビルド警告 0・エラー 0。写しの DB でハーネスから呼んで確認。**アプリを起動しての確認・LAN の実機・HTTPS 側は未確認。**
- 直していない指摘（報告のみ）: /api/my/loadout は DB 使用中のあいだ止めるまで待ち続ける。`top=`（空）が 400。積載量・予算の受け付けが画面と少し違う（+96・空白・NaN）。価格の取り直し中に一覧が 500 になりうる（推測）。要求数に上限なし。

- 道具: scratchpad の venv に fonttools 4.67.0・skia-pathops 0.9.2（利用者の許可）。スクリプトは scratchpad\gfx\bscripts\。
- 元の字詰め 4,473 組・元の漢字の外形は、今の Noto のどの太さとも合わない（元は別の版・別の作り元と推測）。

## v2.3.1: 読み上げを外のアプリに渡す（2026-10-27）
- 利用者の言葉:「しゃべるのを API で他のアプリケーションから呼び出せるようにできますか？ しゃべるアプリにしゃべるタイミングで。exe 指定して指定されたパラメータに {talk} つけるとか、API を指定して呼び出すとか」
- 利用者が決めたこと: exe と API の両方／出力先は VOICEVOX だけ（既定）・外のアプリだけ・両方から選ぶ／値は {talk}・{scene}・{speaker}／版は v2.3.1。
- 親が決めた細部: VOICEVOX の前に呼ぶ。exe は終わりを待たない・窓を出さない。API は 5 秒で打ち切り、2xx 以外は失敗。値の打ち消しは exe 引数（CommandLineToArgvW の規則）・URL（EscapeDataString）・JSON。設定タブに［試す］。
- 「外のアプリだけ」でも「VOICEVOX で読み上げる」のチェックが要る（順番待ちに入る条件を変えていない）。
- ビルドのみ確認（警告 0・エラー 0）。置き換えの関数はハーネスで確認。実際の exe・API の呼び出しは未確認（利用者が公開版で試す）。検証エージェントの結果は公開後に受け取る。
