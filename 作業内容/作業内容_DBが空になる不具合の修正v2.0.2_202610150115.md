# 作業内容: インストール後に DB が空になる不具合の修正（v2.0.2）（2026-10-14〜15）

## 報告された不具合
インストール後、DB が空だった（個人武器の詳細が何も表示されなかった）。

## 調べて分かったこと
- 配布物の DB には中身が入っていた（個人武器 474 件。zip・publish・インストール先で同じ）。
- 空になりうる経路（ソースで確認）:
  1. 起動時の同梱 DB の取り込みを、ファイルの日時だけで判断していた。作業フォルダ側が新しい日時だと取り込まない（起動のたびに書き込むので新しくなりやすい）。
  2. 取り込みで検索用の表（FTS5 の影の表）にも書き込み、COMMIT で全部取り消された。失敗は catch { } で黙殺。
  3. v1.x の DB に item_index.name_key が無く、取り込みが失敗して全部取り消された。
  4. インデックス構築が最初に中身を消し、途中で失敗すると空のまま残った。
  5. 同梱 DB に作者の PC の Data.p4k の日時が入っていて、「パッチ更新あり」が出やすかった。
  6. 最初の写し（約 800MB）が途中で止まると、壊れた DB が残りうる。
  7. 作業フォルダに Program Files の下を選べた。

## 決まり（利用者が決めたもの）
- a = 作業フォルダの今の DB、b = アップデートの同梱 DB またはインポートする DB。
- 「ユーザーが入力したものは残す、他は上書き」。
  - 残す（a 優先、b の分は a とぶつからないものだけ足す）: 手動・CSV・用語集の訳、用語集、チャットの記憶、My Hangar の同期データ、所持船・所持コンポーネント・装備の割り当て、印。キーの無い表は a に 1 行でもあれば a だけ。
  - この PC だけの印（価格の取得中・中止）は a だけ。b からは入れない。
  - ゲームやネットの公開データは b で上書き。

## 直したこと
- 起動時（App.xaml.cs）: 同梱 DB の長さと更新日時を bundled_db_state.json に記録し、違えば同梱 DB を土台に作り直す。DB が無い・壊れている・空でも作り直す。.tmp に作ってから入れ替え、古い DB は .bak に 1 つ残す。失敗は app_log と画面で知らせる。作り直しの間は準備中の窓を出す。
- インポート（DatabaseBackupService.cs, ImportSelectionDialog）: 上の決まりで取り込む。「追加・上書き・全置換」の選択を外した。品目一覧・ベクトル・評判の表も取り込む。取り込む前に 3 つの DB を控え、途中で失敗したら戻す。取り込み中は価格の裏の取得を止める。
- インデックス構築（GameDataExtractor.cs）: 構築前に控えを取り、失敗・中止で戻す。構築が作り直すデータの記録だけを消す（ベクトルなどの記録が消えていた）。wiki のミッション情報を引き継ぐ。
- 「パッチ更新あり」: 構築時に build_manifest.id の Version と RequestedP4ChangeNum を保存し、版で比べる。
- DetectGamePatch: 正規表現が JSON に合わず、いつも "4.0" を返していたのを直した。
- 作業フォルダに書けないときに落ちる箇所を直した。インストーラーで Program Files の下と {app} の下を選べなくした。
- 作者の作業用 DB（D:\temp\gamedata_cache.db）に版の値 2 つ（4.10.197.2878 / 12913470）を手で書き込んだ。Data.p4k の日時と構築日時が一致することを確認したうえで。

## 確認したこと・していないこと
- ビルド: 警告 0・エラー 0。
- 写しの DB での試験: 作り直し・インポート・失敗時の戻しなど、検証エージェントの独立した試験で期待どおり。
- 検証の指摘 10 件を直したあとの再検証は、利用者の指示で打ち切った（執筆側の試験とビルドのみ）。
- 実際のアプリの起動、画面、インデックス構築の控えと戻し、インストーラーの実行は試していない。

## 残り
- v1.x のバックアップをインポートすると、item_index.name_key は次のインデックス構築まで空のまま（古い DB を開いたときの既存の移行と同じ動き）。
- 呼び出し元の無い .sql.gz 形式の取り込み処理が残っている（触っていない）。
