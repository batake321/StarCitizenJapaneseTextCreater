# 作業内容: v2.0.2〜v2.0.5（2026-10-14〜17）

## v2.0.2 インストール後に DB が空になる不具合
- 原因: 起動時の同梱 DB の取り込みが日時比較だけ／FTS の影の表への INSERT で COMMIT が全部取り消し／v1.x の列不足／構築途中失敗で空のまま／同梱 DB の作者 PC の日時で誤った「パッチ更新あり」。
- 利用者の決まり: a = 作業フォルダの DB、b = 同梱 DB またはインポートする DB。「ユーザーが入力したものは残す、他は b で上書き」。
  - 残す: 手動・CSV・用語集の訳、用語集、チャットの記憶、My Hangar 同期データ、所持船・所持コンポーネント・装備の割り当て。この PC だけの印（価格取得中・中止）は a だけ。
  - 上書き: ゲーム・ネットの公開データ全部。
- 同梱 DB は .tmp に作って入れ替え、古い DB は .bak 1 世代。失敗は app_log と MessageBox。インポートも同じ決まりで、「追加・上書き・全置換」の選択は無くした。
- 構築前の控えと失敗時の戻し。gamedata_meta は構築が作り直すキーだけ消す。wiki のミッション情報を引き継ぐ。パッチ更新の判定は build_manifest.id の版で。
- 自動モードの安全チェックが release.ps1 と設定の書き換えを止めた → 利用者が自動モードを抜けて実行。.claude/settings.local.json に release.ps1 と git push の許可を足した。

## v2.0.4
- 船の積載量をゲームデータから（ロードアウトと XML ロードアウトをたどり InventoryOpenContainerType を合計。Centaurus 240）。ゲームデータ → UEX → Ship Matrix、不明は空欄。起動後に未計算なら裏で一度だけ計算。
- ゲームログの購入行に「装備に入れる」。同じ品は数量をまとめ、数量の欄を編集可。ミサイル可。印は my_component_purchases（個人データ）。
- 販売中の船の品名ダブルクリックで［詳細］。
- 装備名のカタカナを英語に（AI 翻訳の指示にルール追加、fix_item_names.py で 70 件＋item_index 54 件）。
- アプリの表示名を今の訳に合わせる: 所持リストは item_record から今の名前を引く。訳・用語集を変えたら item_index の name/name_ja を IniMerger と同じ作り方で作り直し、覚えた名前を捨てる。構築時も translations から作る。
- 価格キャプチャの商品名は items_commodities_ のキーで。コモディティタブは「日本語 (英語)」。採掘の鉱物名を商品の訳に揃えた（5 件）。

## v2.0.5
- ゲームログ: 手掘りの採掘（AttachmentReceived 右手 → 同じ個体の Store で確定、所持数添え）、商品売買に資源名（resource_types を ResourceTypeDatabase から抽出、起動後の裏取り出し）、船名を覚える行を増やす（自分の船の学習元は 4 タグだけ）、他人の船の格納を出さない、「呼び出し完了」。
- チャット: 着る物の口（Char_*）を item_ports に（構築時と起動後の裏取り出し）。「バックパックの口」「胴アーマーの口」「対応」を口のデータから。アンダースーツの耐 G（gForceResistance×100、0 でも 0%）。「フライトスーツ」の別名。システムプロンプトに互換性のルール。
- 起動後の裏の処理は 積載量 → 資源 → 口 の順に 1 本。
- ログに無いもの: 鉱石の品質、岩の種類・場所、ROC・採掘船の採掘量、装備を店で売った記録、納品で品を渡した記録。
