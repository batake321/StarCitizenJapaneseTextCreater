# 作業内容: ［ゲームログ］タブの新設（2026-10-13）

## 目的
Star Citizen の Game.log を読み、ゲーム中の出来事（死亡、契約、売買など）を表で見られるタブを足す。

## 経緯
1. 通信パケットから価格や艦隊の一覧を読めないかという相談があった。
   - 通信は暗号化されている。中身を読むにはアンチチートに触れる方法しかないため、やめた。
2. 代わりに Game.log を調べた。
   - 最新の 5 本と、過去のログ（logbackups）325 本（4 月 16 日〜10 月 12 日、約 600MB）を見た。
   - 局面ごとに、どんな行が出るかを確かめた。
3. 拾う局面を利用者と決めて、実装した。

## 拾う局面と、目印にする行
| 種類 | 目印 |
|---|---|
| 死亡 | `<[ActorState] Dead>`（乗っていた船と場所。相手は出ない） |
| 衝突 | `<FatalCollision>`（同じ時刻・同じ船の行は 1 件にまとめる。相手と場所を添える） |
| 契約受注 | 通知「コントラクト受諾」「契約が成立しました」 |
| 契約完了・失敗・放棄 | `<EndMission>` の `CompletionType`（名前は MissionId で通知から引く。前の回のログからも引く） |
| 目標達成・失敗・撤回 | 通知「目標達成」「目標失敗」「目標撤回／目標中断」 |
| 購入・購入失敗 | `SendShopBuyRequest` / `SendStandardItemBuyRequest` と `RmShopFlowResponse`（結果は、いちばん新しい依頼に結び付ける） |
| 商品購入・売却・取引失敗 | `SendCommodityBuyRequest` / `SendCommoditySellRequest` と `Commodity Transaction Response Error` |
| 量子ジャンプ | `Quantum Drive Arrived`（行き先は直前の `Player Selected Quantum Target`） |
| 区域 | 通知「管轄区域に進入」「休戦ゾーンに進入」「休戦ゾーンを突破」「立入禁止区域から退出」「制限区域から離脱中」「私有地に進入」「私有地を突破」 |
| 呼び出し・格納 | `SetVehicleSpawningInformations` / `StowingVehicle`（船名が分からない時は「船 ID」） |

## ログに無いため、表示できないもの
- 倒した・倒された相手（`Actor Death` は 325 本に 0 件）
- 船での採掘量、精錬
- サルベージの回収量
- 評判
- 一般の店で売ったこと

## 今回は入れなかったもの（利用者の決定）
- 手で掘った鉱物（`Harvestable_Mineral`）。次に採掘した時に、最新のビルドで行の形を確かめてから足す。
- チュートリアル。契約としては扱わない。

## 読み込みの仕組み
- 現在の Game.log は 1 秒ごとに、増えた分だけを読む。タブを開いていない間も読む。
- ゲームを起動し直したことは、ファイルが縮んだか、1 行目（起動時刻入り）が変わったかで見分ける。
  - 見分けたら、新しい Game.log を最初から読む。
  - logbackups に移った前の回のファイルを、過去のログとして読み足す（1 秒ごとに最大 60 回探す）。
- 過去のログ（logbackups\*.log）は、初回の表示時に裏で全部読む。同じファイルを二重に読まない。
- 通知が 2 行に分かれた時は、時刻が同じか 1 ミリ秒遅い 2 行目をつなぎ、先頭の置換文字を取り除く。
  - 2 行目の先頭 1 バイトは、ゲームが書き出す段階で欠けている。元に戻せない。
- 品名・船名は、翻訳 DB と gamedata_cache.db から日本語名に置き換える。
  - DB は読み取り専用で、引くたびに開いて閉じる（Pooling=False）。
  - 店名と商品取引の品目（GUID）は、日本語名にできないので内部名のまま出す。

## 変更したファイル

- `GameLogPanel.xaml`（新規）、`GameLogPanel.xaml.cs`（新規）: タブの画面と読み込み

## 確かめたこと
- ビルド: エラー 0・警告 0。
- 試験用のプログラムに過去のログ 325 本を読ませた。
  - 出た行は 10,232 件で、局面ごとの件数はすべて元のログの行数と一致した。
  - 見本の行で、船名・品名・数量・金額・ミッション名を元の行と照らし合わせた。
- 書き足し中のログを読む試験をした。1〜64 バイトずつ書き足す、ゲームの起動し直しを真似る、の 2 つ。どちらも、一度に読んだ結果と一致した。
