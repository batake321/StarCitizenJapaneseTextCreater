## 入れた物

### 今いる場所で採掘できる物のオーバーレイ
- 新規 `OreHere.cs`（場所の決め方・行の組み立て）、`OreOverlayWindow.cs`（窓）、`MainWindow.OreOverlay.cs`（設定の欄）。設定タブに「現在位置のキーとオーバーレイ」の欄。
- 出すのは、［マップ］の［現在位置］ボタン、現在位置のキー、ステーションの 3D の［現在位置］で座標が取れた後。自動の取得では出さない。既定はオフ、表示 10 秒（0 で出したまま）。
- 場所の決め方: 小惑星の星図の場所 → 近くの天体 → アプリが決めた星系の広がり（Aaron Halo の輪、Nyx の Glaciem Ring・Keeger Belt のガス雲の箱）→ どの場所の中・付近でもないときに限りほかの星系の広がり（今いる星系が分かればその星系だけ）。Akiro Cluster は、ゲームデータに置かれる場所の指定が無いので出せない。
- 中身: 掘り方ごとに岩 1 行（岩・格・出やすさ・シグネチャー・岩の中の資源と割合・倍率）。品質は資源ごとに「最小〜最大（ばらつき）」。**分布と倍率を掛けた数字は出さない**（ゲームがどう組み合わせるかの式がデータに無い）。
- クリックはふだん下へ通す。左 Ctrl + 左 Shift を押している間だけ受ける。左 Ctrl + 左 Shift + クリックで変更中（移動・大きさ）、動かさないクリックで確定、✕ は確定せずに閉じる。
- アプリの画面の取り込み（価格キャプチャなど）に写らないよう、`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` を付けた。

### 品質と広がりの表
- gamedata_cache.db に `ore_quality`（66 行）・`ore_rock_parts`（800 行）・`ore_areas`（181 行）を足した。既存の ore_locations（6,115 行）・ore_signatures（34 行）は変えていない。
- 前の版の DB には起動後の作り直しで入る。**公開の前に、開発機の作業フォルダの DB へ画面なしで入れた**（新しい引数 `--rebuild-ore-tables [作業フォルダ]`。81 秒、終了コード 0）。配る DB には初めから入っている。
- 品質のデータ（Game2.dcb、sc-alpha-4.10.2）: 資源ごとの分布（`ResourceTypeCraftingData.qualityDistribution`）、星系の上書き（Pyro だけ）、岩の中の行ごとの `qualityScale`（1 / 0.789 / 0.49）。

### 現在位置のキー
- 新規 `MapCurrentHotkey.cs`。既定「左 Ctrl + 左 Shift + Insert」・使う。設定で変えられる・使わないにもできる。ゲームの既定の割り当てと利用者の割り当てに Insert は 0 件。
- `RegisterHotKey` は左右を区別しないので、キーが来たときに `GetAsyncKeyState` で左のキーが押されているかを見る。右のキーでは動かないが、Ctrl + Shift + Insert はほかのアプリに届かなくなる。
- キーのときは、アプリの窓・3D の窓を前に出さない（ボタンのときは今までどおり）。

### 設定の保存の直し
- 窓の位置の既定値（NaN）のまま設定を保存すると例外になり、設定ファイルが書かれなかった。NaN の Window* は鍵を書かない形にした（`MainWindow.xaml.cs` の `BuildConfigJson`）。

### データベースだけの更新
- `AppUpdater.cs`: 最新のリリースの版がアプリと同じとき、manifest の DB 4 つ（gamedata_cache.db・translations.db・equipment_cache.db・view3d_layout.db）だけを比べ、違えば「データベースの更新があります」と知らせる。版が新しいときの流れは変えていない（view3d_layout.db を差分で取るようになった所だけ違う）。
- DB の SHA-256 は、大きさと更新日時が同じ間は覚えを使う（版が同じときだけ）。
- 新規 `release_db.ps1`: DB だけを同じ版のリリースへ出す。`-DryRun` で何も載せずに作る物だけ出す。manifest は「別の名前で載せる → 前を消す → 名前を変える」。**v2.6.4 を公開した後でないと動かない**（最新のリリースと版が同じことを確かめる）。
- `release.ps1`: push の失敗で止める（今までは失敗しても「Push OK」と出て進んでいた）。リリースを下書き（target_commitish = push した HEAD）で作り、添付を全部載せてから公開に切り替える。公開してから manifest が載るまでの間に前の版のアプリが確かめると「手で入れてください」と出て見送ってしまうのを防ぐため。
- 新規 `StationLayoutBundled.cs`: 同梱の view3d_layout.db の作った時刻（built_utc）が置き場所の物より新しいときだけ写す（3D を開いていないとき）。

### 武器・装備の 3D と資源
- 原因 A: 本体の形が CDF の Model File に入っている品（CQ7 など 35 件）で、付属品の最初の物（弾）を本体にしていた → Model File に形があればそれを本体にする。Arlington Rifle も出る。
- 原因 B: アーマー・アンダースーツ・服は主の形が箱で、品の形は SubGeometry にある → しまってある形 → 着る形の順で出す（3,537 件）。
- 原因 C: 面を隠す決まりが `%DECALS` を `%DECAL` と取り違えていた → 語で見る形に直した。**船とステーションにも広げた**（Hammerhead +1,396 面、GrimHEX +16,083 面。本物のデカールは隠れたまま）。ステーションの取り出し結果の保存の版は region-cache-8。
- 原因 D: 小さい品を半径 0.5 m 以上として画角を決めていた → 品は実際の大きさで。
- 品と船の「取り出しの処理の版」（`ItemExportVersion`・`ShipExportVersion`）: 版の古い品・船は、次に開いたときに取り込み直す。裏で全部を取り込み直すことはしない。［船舶・車両をまとめて取り込む］は押せるようになる。
- ［詳細］で、採掘できない資源（132 件）は種類「コモディティ」と出し、【採掘できる場所】の節を出さない。

### ［詳細］の 3D の欄の高さ
- 詳細の文と 3D の欄の間に、上下にドラッグできる仕切り（`DetailPanel.xaml` の `split3D`）。高さは覚える（`Detail3DHeight`、既定 340）。

### 船内を歩くモード
- 新規 `wwwroot/ship3d/walk.js`。ステーションの歩くモード（`wwwroot/stationmap/view3d.js`）の計算と決まりの数字を、同じ名前・同じ値で船の 3D へ写した。ステーションのファイルは変えていない。
- ［船内］のとき［歩くモード］［走る］［姿勢］［すり抜け］。歩く 2.8・走る 10 m/秒、段 0.6 m、ジャンプ、よじ登り、しゃがむ・寝そべる、はしご、すり抜け。
- 船だけの直し: 入った所で立てないときは近くの立てる床から始める／よじ登りで天井を抜けない／ドアは足元の升にも入れない（歩いて抜けられる）／縦に並んだはしごの部品を 1 本にまとめる／キーは `e.code` で見る。
- 入れていない物: エレベーター・無重力・録画とコメント・歩いて床を補う仕組み。はしごのエンティティ（船の取り込みが読み飛ばしている `Ladder`）は足していない。
