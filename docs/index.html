Star Citizen Japanese Text Creator
使い方マニュアル

Star Citizen のゲーム内テキストを日本語にして、ついでに交易・所持船・契約調べまで面倒を見る Windows アプリです。
このページでは、初めて起動したところから一通り使えるようになるまでを図解で説明します。

Windows 10 / 11 .NET 10.0 翻訳済み DB 同梱 (Patch 4.10.2 対応) AI 翻訳は任意

1このアプリでできること

大きく分けて 3 つのことができます。どれか 1 つだけ使っても構いません。

ゲームを日本語にする

ゲームの Data.p4k からテキストを取り出し、翻訳データベースの日本語を当ててゲームに書き戻します。AI に翻訳させることもできます。

遊ぶための情報を引く

交易ルートの計算、所持船とアップグレード権利の管理、装備の登録、契約一覧の検索ができます。

AI に日本語で質問する

ゲームデータや外部 API を AI に調べさせて日本語で答えさせます。ブラウザ・スマホからも使え、音声で読み上げさせることもできます。

翻訳だけ使うなら、簡単に使えるようにしました。

翻訳済みのデータベースが初めから入れてあるので、日本語化 ボタンを押して、ゲーム内で表示される名前に便利なオプションを付けるか選んで 実行 ボタンを押すだけです。API キーも AI の設定も要りません（同梱版は Patch 4.10.2 対応）。

AI翻訳 を使うのは、次の 2 つの場合だけです。

  • 同梱の翻訳データがまだ対応していない新しいパッチが来て、増えた分を自分で訳したいとき
  • 訳の言い回しを自分好みに変えたいとき

2動作要件とインストール

動作要件

  • Windows 10 / 11
  • .NET 10.0 Desktop Runtime（x64）— インストーラーなら無ければ自動で入ります。zip の exe は、.NET 10 が無ければ起動時にダウンロードの案内が出ます
  • Star Citizen がインストールされていること
  • AI 翻訳や AI チャットを使う場合のみ（いずれか 1 つ以上）
    • Claude API キー / Gemini API キー / OpenAI (ChatGPT) API キー
    • Ollama ＋ Gemma4（ローカル実行・無料。おすすめは gemma4:e2b / gemma4:e4b。→ 設定方法）
  • 音声読み上げを使う場合のみ（任意） — VoiceVox（無料の音声合成エンジン）
  • My Hangar 同期を使う場合のみ — WebView2 ランタイム（Evergreen）。Windows 10 / 11 には通常インストール済みです

インストール

  1. 上の表から アプリ本体 (zip) をダウンロードします。
  2. 好きな場所に展開します。zip 版はインストール作業なしで動きます。
  3. 展開したフォルダの中の実行ファイルを起動します。

アプリを新しいバージョンに入れ替えたときは、翻訳タブの 日本語化 → 実行 を一度行ってください。同梱の翻訳データベースが新しくなっていれば、起動時に同梱のものを元に作り直されますが（手動・CSV・用語集で入れた訳、用語集、チャットの記憶は引き継がれます）、ゲーム側のファイルに書き出すのは 日本語化 の役目です。

4最短セットアップ

まずはここだけやれば、ゲームが日本語になります。

  1. アプリを起動します。上部の GamePath に Star Citizen のインストール先が自動で入っていることを確認します。空欄なら 参照... から選んでください（RSI Launcher のログから自動検出を試みます）。
  2. 右隣のコンボボックスで LIVE / PTU など、日本語化したいチャンネルを選びます。
  3. 翻訳 タブで 日本語化 を押し、オプションを選んで 実行 を押します。これだけです。
  4. Star Citizen を起動して、日本語になっていれば完了です。

ここまでで AI の設定は一切要りません。同梱の翻訳データ（Patch 4.10.2 対応）がそのまま当たります。新しいパッチで増えた分を自分で訳したい、あるいは訳を書き換えたいという段になって初めて、AI 設定 と AI翻訳 の出番です。

読み取りボタンの版とチャンネル

読み取りのボタンには、ゲームの版とチャンネルが出ます（例 4.10.2 LIVE を読み取る）。版はチャンネルのフォルダの build_manifest.id から読みます。読めないときは今までどおり 新しいパッチを読み取る と出ます。

  • 新しい版が LIVE・PTU にあるとき、ボタンが黄色になります。前に読み取った版より新しい版が入っているチャンネルを、ボタンの文字に出します（選んでいるチャンネルが新しければそれ、違えば LIVE を先に出します）。押すと、そのチャンネルに切り替えてから読み取ります。
  • 上の GamePath バーのチャンネルのリストには、LIVE と PTU が必ず並びます。Data.p4k の無いチャンネルは灰色になり、選べません。
  • ボタンの文字は、アプリの窓が前に来たときに読み直します。

チャットのコマンドは英語のまま

/party・/addfriend などのチャットのコマンドの名前は、日本語にせず英語のまま書き出します。日本語にするとゲームでコマンドが通らないためです。前の版で日本語化した方は、日本語化 → 実行 をもう一度行うと反映されます。

装備名の分類 — 分類・サイズ・グレードが名前で分かる

装備名の後ろに分類を付ける にチェックを入れて 実行 すると、ゲーム内の装備名の後ろに [軍1C] のような印が付きます。名前を見ただけで分類とサイズとグレードが分かります。

印ゲーム内の表記
産Industrial
軍Military
市Civilian
隠Stealth
競Competition

漢字のうしろの数字がサイズ、英字がグレードです。[軍1C] なら「軍用のサイズ 1、グレード C」です。分類はアイテムの説明文にある Class: の行から取っているので、ゲームが持っている情報そのままです。

印が付くのは、分類を持つ装備 472 品目です。パワープラント、シールド、クーラー、量子ドライブ、レーダーなどが対象で、分類を持たない船舶武器や個人装備には付きません。

契約名に設計図を付ける にチェックを入れると、設計図（ブループリント）がもらえる契約の名前のうしろに [BP] が付きます。Shubin の採掘発注や Wikelo のレシピなど 12 件です。

装備名の印には色を付けていません。機体ロードアウトマネージャーの装備名欄はゲームの強調タグを解釈せず、<EM4> という文字がそのまま見えてしまうためです。契約名の印だけ色が付きます。

契約名の派閥と貢献度 — 受ける前に分かる

契約名に派閥と貢献度を付ける にチェックを入れて 実行 すると、契約名の後ろに [バウンティーハンターズ・ギルド +50] のような印が付きます。どの派閥の評価がいくつ上がる依頼なのか、受ける前に分かります。

初回はデータの取り込みに 30 秒ほどかかります。装備データを再抽出 を実行したときにも一緒に取り込まれます。

同じ名前の契約がまとめて扱われることがあります。ゲーム側で契約名が使い回されているためで、その場合は [+50/100/200] のように取り得る値を並べます。派閥が複数に割れるときは派閥名を出さず、値だけを出します。英語圏の同種の MOD も同じ作りです。

6AI 設定 — 翻訳バックエンドの登録

日本語にしたいだけなら、この章は飛ばして構いません。翻訳データは同梱されているので、AI の登録なしで 日本語化 → 実行 だけで日本語になります。ここが必要になるのは、新しいパッチの未翻訳を自分で訳したいときと、AI チャットを使いたいときです。

上部バーの AI 設定（または 設定 タブの AI 設定を開く）で、翻訳とチャットに使う AI を登録します。

  1. バックエンド追加 で行を増やします。
  2. 種類（Claude / Gemini / OpenAI / Ollama）、API キー、モデル名を入れます。
  3. 翻訳に使いたいものだけチェックを入れます。
  4. 保存 で閉じます。

チェックボックスは「翻訳に使うかどうか」の選択です。チェックを入れたバックエンドが同時に走ります。チャットで使うバックエンドは、チャットタブ側のコンボボックスで別に選びます。

ダイアログの下の E2B / E4B を翻訳に使う は、モデル名に gemma4:e2b / gemma4:e4b を含むバックエンドを AI翻訳 に使うかの設定です。最初はチェックが外れています（使わない）。

  • チェックが外れていて、ほかに翻訳に使うバックエンドがあれば、聞かずに E2B / E4B を除いて翻訳します。
  • チェックを入れているとき、または翻訳に使えるのが E2B / E4B だけのときは、翻訳の前に「E2B / E4B を翻訳に使いますか？」と聞かれます。いいえ なら E2B / E4B を除いて翻訳します（ほかに使えるバックエンドが無ければ翻訳しません）。

ゲームをしながらの翻訳には向きません。Ollama は GPU の VRAM を使います。Star Citizen も VRAM を大量に使うため、ゲームプレイ中に翻訳やチャットを実行するとゲームのパフォーマンスが落ちることがあります。ゲーム中は避けるか、軽い gemma4:e2b を使うか、別 PC の Ollama に接続してください（Base URL を http://192.168.x.x:11434 に変えます）。Claude / Gemini などのクラウド API なら VRAM への影響はありません。

翻訳がパースエラーで失敗する場合（ログに「パース失敗 (0行)」と出る場合）は、Ollama のコンテキスト長不足が原因のことがあります。環境変数 OLLAMA_NUM_CTX=8192 を設定するか、Batch を 1〜5 に減らすと改善することがあります。

7翻訳エディタ — 訳文の確認と手直し

AI の訳が気に入らないときや、特定の語を探したいときに使います。

探す

  • 検索欄に語を入れて 検索。部分一致（既定でオン）を外すと完全一致になります。
  • 検索欄の右に並ぶコンボボックスで検索対象を 全フィールド / Key / English / Japanese から選べます（画面上にラベルはありません）。
  • その隣のソース絞り込みで、訳がどこから来たのかで絞れます。
    • official — ゲーム同梱の公式日本語
    • ai — AI が訳したもの
    • manual — 手で直したもの
    • csv — CSV から取り込んだもの
    • glossary — 用語集の一括置換によるもの
    • original — 原文のままにしたもの
    • untranslated — まだ訳されていないもの
  • さらに右のコンボボックスでは、どの AI が訳したかで絞り込めます。

バインディング編集 — 押して割り当てる

機能別 タブで行をダブルクリックすると開きます。現在のバインド の機器の欄をクリック（または Tab で移る）か、その欄の 設定 を押して機器を選び、下の一覧から入力を選んで割り当てます。一覧から選べるジョイスティックのボタンは Btn 1〜Btn 128 です（ほかに軸・スライダー・Hat1・Hat2）。

  • 選んだ欄には赤い枠が付きます。開いた直後はどの欄も選んでいないので、下の一覧は出ず、クリア も押せません。
  • 下の「設定:」の行には、選んでいる機器の今の割り当てが出ます（割り当てが無い・解除したときは「設定: なし」）。
  • クリア は、選んでいる欄（赤い枠）の割り当てを消します。窓には「割り当てを削除するときは、消したい機器の欄をクリックして選び（赤い枠が付きます）、［クリア］を押してください。」と出ています。
  • 窓を開いたまま ゲームパッドか HOTAS の入力を押すと、黄色の確認欄が出ます。押された入力（HOTAS の js 番号が分かっていれば、機器の名前は actionmaps.xml の機器の名前。例 VKBsim Gladiator EVO L）、この機能の（機器）の今の割り当て（解除した割り当ては「なし」）、この入力を使っている他の機能 が並びます。修飾キー: のチェックは、押した入力に付けて出ます。
  • 反映 で、押した入力をその機器の欄に入れます。キャンセル で何もせずに確認欄を閉じます。窓の OK で確定します。
  • 「この入力を使っている他の機能:」は 1 機能 1 行で、各行の右に 変更 削除 があります。
    • 削除 — その機能の、押した入力の機器の割り当てを消します。
    • 変更 — 「割り当ての変更」の窓が開き、「「（機能名）」を割り当てるボタンを押してください。」と出ます（機器・今の割り当てと、修飾キーがあれば「(修飾キー … は引き継ぎます)」も出ます）。同じ機器（HOTAS は同じスティック）のボタンかハットを押すと、押した入力と「割り当て済みの機能:」が出ます。反映 でその機能をそのボタンに変え（修飾キーは引き継ぎます）、中止 では変えません。別の機器の入力は「別の機器の入力です。…のボタンを押してください。」（別のスティックなら「別のスティック (…) の入力です。…」）と出て受け付けません。
    • どちらもその場では変えず、予定として行に「→ 削除」「→ （入力） に変更」と出ます。予定は行の 取消 で取り消せます。
    • 確認欄を閉じても予定は残り、窓の下に「ほかの機能の変更・削除の予定: N 件 (［OK］で確定し、［キャンセル］で取り消します)」と出ます。バインディング編集の OK で確定し、キャンセル で取り消します。

js 番号が分からない機器

押した HOTAS が js1 か js2 かは、保存データの actionmaps.xml の機器の定義（options の Product）から決めます。決められない機器を押すと「どの js 番号か判別できません」と出て、この機器は: の js1 (HOTAS L) / js2 (HOTAS R) のボタンで手で選べます（L / R は今の HOTAS の左右の選択で変わります）。HOTAS タブとバインディング編集のどちらでも選べます。

  • 選んだ番号は、その保存データの機器の定義ごとに作業フォルダに覚えます。
  • 手で選んだ番号の機器を押したときは、HOTAS タブに「手で選んだ js◯ として表示しています」、バインディング編集に「(js◯・手で選んだ番号)」と出て、選び直すボタンも出ます。

HOTAS の左右

HOTAS の左右（どちらが HOTAS L / HOTAS R か）は、機器の名前からは決めず、利用者の選択で決めます。

  • 左右をまだ選んでいない保存データで、actionmaps.xml にスティックが 2 本以上あると、エディターを開いたときに「HOTAS の左右」の窓が出ます。左右の表示だけが変わり、ファイルは変わりません。
  1. 「左スティックのボタンをどれか押してください。」と出るので、左手のスティックのボタン（かハット）を押します。
  2. 押したスティックが左、もう一方が右の枠で並びます。枠には大きく Stick1 / Stick2（js1 / js2）、その下に機器の名前が出ます。
  3. 「左右のスティックのボタンを押して確認してください。」と出ます。左右のスティックのボタンを押すと、押した側の枠がオレンジに光ります。
  4. 左右が違っていれば 入れ替え、よければ OK を押します。最初のボタンを押すまでは、OK と 入れ替え は押せません。
  • どのスティックか分からない機器を押すと、「どのスティックか分かりません (機器の名前)。このスティックは:」と Stick1 Stick2 が出ます。選ぶと、その番号を覚えて続けます（エディターの「この機器は:」と同じ記録です）。
  • エディターを開いたときに出た窓で OK を押すと、「あとで［HOTAS］タブの［左右を設定…］（ボタンを押して設定し直す）か［表示の入れ替え］（左右を反転する）で変えられます。」と出ます。選んだ左右は、保存データの機器の定義ごとに作業フォルダに覚えます。
  • 中止（または窓を閉じる）では何も保存しません。エディターを開いたときに出た窓なら、今回は js1 = 左手・js2 = 右手 で表示し、次に開いたときにまた聞きます。窓には「スティックを接続していないときは［中止］を押してください (あとで［HOTAS］タブの［左右を設定…］で設定できます)。」と出ています。
  • HOTAS タブの 左右を設定… でも、この窓を開いて設定し直せます（左右を選んだあとでも開きます）。ここから開いたときは、OK のあとの知らせは出ません。

js1 と js2 の入れ替え

HOTAS タブの上には 表示の入れ替え 左右を設定… js1/js2 の入れ替え の順にボタンが並びます。左右を設定… は上の「HOTAS の左右」の窓を開きます。入れ替えのボタンは次の 2 つです。

  • 表示の入れ替え — HOTAS の左右の選択（js1 = 左手・js2 = 右手 か、js1 = 右手・js2 = 左手 か）を反転するだけです。表示だけで、ファイルは変わりません。選んだ左右は、保存データの機器の定義ごとに作業フォルダに覚えます。
  • js1/js2 の入れ替え — 確認のあと、全ての機能の js1 と js2 の割り当てを入れ替えます。割り当てといっしょに、activation mode と既定の割り当ても入れ替わります（デフォルトに戻す は入れ替えた後の既定を入れます）。保存すると、actionmaps.xml の joystick の instance="1" と instance="2" の設定（Product など）も入れ替わります。物理スティックの左右は変わらないので、HOTAS の左右の選択も反転します。2 回押すと元に戻ります。

js1/js2 の入れ替えを保存すると、入れ替える前の js1 の機器を作業フォルダに記録します（記録が無いときだけ）。次に保存データを開いたとき、js2 がその機器で js1 がそうでなければ入れ替え済みとして、既定の割り当てと既定のモードを左右入れ替えて使います。記録が無い、機器の定義が無い、js1 と js2 が同じ機器、どちらにも当たらない、のときは入れ替えていないものとして扱います。

  • 記録が無くても、次のときは記録せず、そのことを知らせるだけです。前に記録のファイルが壊れたことがあり、控え（.broken-*）が残っているとき（控えを直して元の名前に戻すか、控えを消すと、次に入れ替えを保存したときに記録します）。保存データの options に js1 / js2 の機器（Product）が書いていないか、js1 と js2 が同じ機器のとき。
  • 記録があっても、保存したデータの機器と合わないときは、記録は変えずに「入れ替え済みかを決められません」と知らせます。
  • HOTAS タブに「元の js1 の機器: （名前） （VID:PID など）」と、この保存データの判定が出ます。記録が無ければ「元の js1 の機器: 記録なし (js1/js2 の入れ替えを保存したときに記録します)」、入れ替えが保存待ちのときは「元の js1 の機器: 記録なし (保存すると、入れ替える前の js1 の機器を記録します)」と出ます。
  • 記録を消す — 確認のあと、元の js1 の機器の記録を消します。消すと、どの保存データも入れ替えていないものとして扱い、次に js1/js2 の入れ替えを保存したときに記録し直します。記録が無いときは押せません。

割り当ての解除

  • 割り当ては、キーやボタンの割り当ての窓の 解除（確認のあと）や、バインディング編集の クリア（選んでいる欄の割り当て）で解除します。
  • 解除した割り当ては、画面では空になります（機能別 タブの HOTAS の欄では、解除した側の行は出ません）。ゲームの解除の書き方（機器の接頭辞と空白。kb1_ 、js1_ など）で持ち、保存すると actionmaps.xml にその書き方で書きます。
  • 解除した割り当ては、バインドの数や、入力種別の絞り込み（キーボード / マウス / ゲームパッド / HOTAS）では割り当て無しとして数えます。未割当のみ では、解除した機能も出ます。

保存 — 上書き保存と新規作成

窓の下の 保存 を押すと、保存方法を選ぶ窓が出ます。

11コモディティ — 交易ルートを探す

UEX の価格データを元に、どこで何を買ってどこで売れば一番儲かるかを計算します。

ルートを探す

  1. 船: を選ぶと 積載 (SCU) が自動で入ります（所持船に登録した船が候補に出ます）。
  2. 予算 (aUEC)、買い星系: / 売り星系:（全て / Stanton / Pyro / Nyx）を指定します。
  3. 必要なら コモディティ選択 (全て) で扱う商品を絞ります。
  4. 絞り込みのチェックを調整します。
    • 地上小規模拠点を除く（既定でオン）— 着陸が面倒な小拠点を候補から外します
    • 外部積込対応のみ (Hull C等) — 外部グリッドに積む船向け
    • 在庫不足ルートを除く — 在庫が足りない拠点を外します
  5. ルート検索 を押します。価格が古いと感じたら 価格更新 で取り直します。

拠点ごとに見る

結果の行を選ぶと 購入場所 (安い順) と 売却場所 (高い順) の詳細が開き、差益と相手先がわかります。閉じるときは ✕ を押します。

価格は UEX に集まったプレイヤーの報告です。実際のゲーム内価格と食い違うことがあります。ずれを見つけたら 価格キャプチャ から報告できます。

12船舶管理 — 所持船・アップグレード・装備・電力管理

所持船 — 持っている船を登録する

ここに登録した船は、コモディティタブの船セレクタにも出てきます。

  • 手で追加する場合 — 船を追加 の 検索: に船名を入れて 検索、候補から選んで 追加。aUEC で買った船は ゲーム内購入 (aUEC) にチェックを入れます。
  • まとめて取り込む場合 — My Hangar と同期（下で説明）のあと 同期した船を所持船に反映。手で入れた分は保護されます。
  • 各行の アップグレード / 装備 ボタンから、それぞれのタブへ飛べます。
  • 船名（1 列目）をダブルクリックすると、詳細 タブでその船を開きます（→ 19）。船の品目が決まらないときは、詳細 の名前の欄に船名を入れて検索した状態で開きます。
  • 船名以外の列をダブルクリックすると、その船が 船を追加 の入力欄に読み込まれて編集できる状態になり、同時に 装備 タブの 現在の装備 もその船に切り替わります（表示中の画面は所持船のままです）。メーカー欄が空でも船名から自動で判別します。
  • ワイプ を押すと、サーバーワイプで無くなる船を選んでまとめて削除できます。ゲーム内 (aUEC) で買った船には既定でチェックが入り、pledge の船は既定で外れます。Wikelo の報酬などワイプ後も残る船はチェックを外してください。
  • 船名は 3 文字以上入力すると候補が出ます。一覧から選ぶか、そのまま打ち込んでも構いません。
  • メーカーは船名を入れた時点で自動で埋まります。一覧から選び直すことも、直接入力することもできます。登録済みの船でメーカーが空のものは、所持船タブを開いたときに自動で埋まります。
  • ローナー 列に、その船を持っていると借りられる機体が出ます。まだ飛べない船を持っている場合、代わりに使える機体がここで分かります。一覧は UEX から取り込んでいます。

My Hangar 同期 — RSI アカウントから読み取る

  1. My Hangar と同期 を押すと「My Hangar 同期」ウィンドウが開きます。
  2. 内蔵ブラウザ (WebView2) に RSI のページが出るので、そこでご自身でログインします。
  3. 同期開始 で、保有 pledge・船・保険・アップグレード権利 (CCU) を読み取ります。
  4. 次回から入力を省きたい場合は ログイン状態を保持する にチェックを入れます。

アプリは ID / パスワードを扱いません。ページ上のクリックや送信も行わず、表示されている内容を読み取るだけです。ログイン状態を保持する を使う場合、ログイン情報は Windows のデータ保護 API (DPAPI) で暗号化して保存されます（このユーザーアカウントでしか復号できません）。

アップグレード管理 — CCU と melt を試算する

保有している船と、使えるアップグレード権利 (CCU) の対応を一覧します。実際に RSI 側で何かを実行するわけではなく、手元でのシミュレーションです。

  • Upgrade で権利を当ててみて、連鎖させ、Undo で戻せます。シミュレーションをリセット で全部戻します。
  • 権利（CCU）の色は 緑 = いま使える、紫 = このシミュレーションで適用中、灰 = 使用不可（元の船を持っていない、または売却予定にした船が起点）です。船の行が灰色になっているものは、使える権利が無く適用もしていない船です。
  • Sell で pledge 単位の売却 (melt) を試算します。現在の Store Credit、売却で得られる Credit、失う機体、LTI 喪失警告、Buy Back の残トークンが表示されます。
  • 販売中の船 (RSI ストア) を開くと、いま売られている船・パック・アップグレードが見られます。Warbond のみ で絞り込めます。情報が古ければ ストア情報を更新。船/商品 の欄をダブルクリックすると 詳細 タブで開きます（→ 19）。船の品目が決まらないとき（船でない商品を含む）は、詳細 の名前の欄にその名前を入れて検索した状態で開きます。
  • プランナー / melt シミュレーション では、船ごとに「要る / 要らない / 保留」を付けて 提案を計算 したり、目標価格から逆算したりできます。

装備 — 持っているコンポーネントと船の装備

  • 所持コンポーネント に、パワープラント / シールド / クーラー / 量子ドライブ / 船舶武器などを、使用可のチェックや数量を含めて登録します。
  • 現在の装備 で船を選び、ポートごとに何を積んでいるかを設定します。設定していないポートは「現在」列にも初期装備がそのまま表示されます（灰色の文字）。自分で設定したポートだけが青い太字になり、行の背景も青くなります。
  • 所持船 の行の船名以外の列をダブルクリックするか、行の 装備 ボタンを押すと、その船の装備をここで開けます。
  • どこで買えるかを知りたいときは、装備の名前にマウスを乗せます。デフォルト / 現在 列、装備を設定 の候補、所持コンポーネント の名称、どれのツールチップにも UEX の購入場所と価格が出ます。
  • 購入先はアプリの起動後にバックグラウンドで取り込みます。まだ取れていない間は 取得中… と出ます。船に最初から付いている装備は店で売られていないことが多く、その場合は 購入先の登録がありません と出ます。
  • 全てデフォルトに戻す で初期装備に戻せます。
  • 装備の表・所持コンポーネントの表・船名のツールチップは、裏で読み込みます。データベースが使用中のときは「読み込み中... ({名前} が使用中のため待っています)」、時間がかかっているときは「読み込み中... (時間がかかっています。{名前} が使用中なら、空くまで待ちます)」と出て、空いたら自動で読み直します（{名前} は gamedata_cache.db など。分からなければ DB）。読み込みの間、装備の表と所持コンポーネントの表はクリックできず、選択を削除 品質を入力 も押せません。別の船を選ぶと、前の船の行はすぐに消えます。
  • 所持コンポーネントの使用可や数量を変えたとき、その行が既に無かった（読み込みでほかの行にまとめられた、など）ときは、変更は入らず、状態の欄に「「（品名）」の行が既に無かったため、使用可の変更は入りませんでした」（数量のときは「数量の変更は入りませんでした」）と出て、表を読み直します。
  • 設定した内容は、船名にマウスを乗せたときのツールチップにも反映されます。
  • 所持コンポーネント の 名称、現在の装備 の デフォルト / 現在 の装備名をダブルクリックすると、詳細 タブにその品目を出します。
  • 船のゲームデータにある既定の装備は、詳細 タブで船・車両を開くと 【船・車両】 の下に表で出ます（→ 19）。

自作したコンポーネントの品質 — 品質 の列と 品質を入力

クラフトで作った部品は、材料の品質で性能が変わります。所持コンポーネント には、材料の枠ごとの品質（0〜1000）を登録できます。

  • 品質 の列は、全部の枠が同じ品質なら Q950 のように、枠ごとに違えば Q 枠ごと と出ます。品質を入れていない行は空です。
  • 行を選んで 品質を入力 を押すと「品質」の窓が開きます。このボタンは、選んだ部品の BP（ブループリント）に品質の増減があるときだけ押せます。BP のデータは設定タブの インデックス構築、または起動後に裏で行う取り出しで入ります（→ 27）。起動後の取り出しが終わると所持コンポーネントの一覧も読み直すので、そこから押せるようになります。
  • 窓には、BP の材料の枠ごとに、枠の名前・品質の入力欄・その枠で変わる性質が並びます。全部の枠に同じ品質: に数を入れて 当てる を押すと、全部の枠にその品質が入ります。品質は 0〜1000 の整数だけを入れられます（ほかの値では「品質は 0〜1000 の整数で入れてください」、枠の欄なら「（枠の名前）: 品質は 0〜1000 の整数で入れてください」と出て閉じません）。
  • 少なくとも 1 枠に品質を入れたときは、空の枠は品質 500（ゲームデータの既定の品質）として計算します。全部の枠を空のまま OK を押すと、品質なしにする と同じ（品質なし）になります。
  • 数量が 2 以上の行では 品質を入れる数: が出ます（既定は全部）。全部より少なくすると、その数だけ別の行に分けて品質を入れます。数が 1〜数量の整数でないと「品質を入れる数は 1〜（数量） の整数で入れてください」と出て閉じません。品質なしにする もこの数に従い、全部より少なければ、その数だけが品質なしの別の行になります。
  • 入れた品質がもとの行と同じなら、行は分かれません。分けた数は、同じ部品・同じ使用可・同じ品質の行が既にあれば、その行の数量に足されます。
  • 同じ部品でも、品質が違えば別の行になります（同じ部品・同じ使用可・同じ品質の行は 1 行にまとまります。まとめると数量は合計され、メモは「 / 」でつながります）。
  • 品質なしにする で品質を消します。OK で保存、キャンセル で何もしません。
  • 窓を開いている間にその行の数量が変わっていたときは、品質の変更は入らず、状態の欄に「「（品名）」の数量が ×（窓の数量） から ×（今の数量） に変わっていたため、品質の変更は入りませんでした」と出て、表を読み直します。行が既に無かったときは「「（品名）」の行が既に無かったため、品質の変更は入りませんでした」と出ます。読み込みの間は 品質を入力 を押せません。
  • 品質から出る性能は、BP の品質の増減から計算して 電力管理 で使います（下の節）。性能 の列は部品の元の値のままで、品質では変わりません。

電力管理 — 電力のピップを割り振って試す

船を 1 隻選び、電力に関わる部品（パワープラント・クーラー・シールド・レーダー・生命維持・量子ドライブ・船の武器）に電力のピップを割り振ったときの、出力の残り・冷却剤・シールド・武器の DPS を見るタブです。値はゲームデータ（gamedata_cache.db）から計算します。ここで替えた部品・割り当て・品質は保存しません（装備 にも書き戻しません）。

船と部品を選ぶ

  • 所持船 — 装備 の船セレクタと同じ一覧です。最初の部品は 装備 の現在の装備になります。
  • 全船 — 詳細 タブと同じ船の一覧です（テンプレートなどを除き、同じ英語名の船は 1 つにまとめます）。最初の部品は既定の装備になります。
  • 部品の候補: — 所持コンポーネント か 全部品 を選びます。どちらも、装備 と同じ条件で、その搭載枠に付けられるものだけが候補になります。各行の 部品 の欄で、同じ種類の部品に替えられます（最初の候補は「(現在の装備)」）。武器の行は武器だけで、ジンバルの付け替えはしません。
  • 候補を替えても、部品と割り当てはできるだけ残ります。船を替えると、行は作り直されます。
  • 読み込みは裏で行い、表の上の状態の欄に「読み込み中...」と出ます。データベースが使用中のときは「読み込み中... ({名前} が使用中のため待っています)」、時間がかかっているときは「読み込み中... (時間がかかっています。{名前} が使用中なら、空くまで待ちます)」と出て、空いたら自動で読み直します（{名前} は gamedata_cache.db など。分からなければ DB）。
  • タブを開き直したときは、船か 装備 の現在の装備・所持コンポーネントが変わったときだけ読み直します。インデックス構築・装備データの再抽出・バックアップの取り込みなどのあとは、必ず読み直します。読み直しても、現在の装備が前と同じ搭載枠では、選んでいた候補・割り当て・オン/オフ・全部品の候補に入れた品質を残します（選んでいた候補が無くなっていれば、現在の装備・最大に戻ります。「(現在の装備)」の行に入れた品質は残りません）。武器のプールの割り当ても残します。

ピップを割り当てる

  • 割り当て の欄の − ＋ でピップを増減します。段は オフ（0）、動くのに要る最低のピップ〜最大です（最低のピップより少なくすると「オフ」になります）。最小〜最大 の欄に範囲が出ます。
  • 量子ドライブなど、ピップでない部品は オン のチェックで入・切します。電力使用量は単位が違うため、出力の計算には入れません。
  • 武器は、船の武器全部で 1 つの 武器のプール の行（武器の電力 (FixedPowerPool)）のピップを分け合います。この行は、武器の行が 1 つ以上あり、船のデータにあるプールの大きさが 0 より大きいときだけ出ます。プールのピップは出力から引きます。0 ピップでは武器が撃てません。
  • 全部最小 — ピップの部品を動く最低のピップに、武器のプールを 0 に、量子ドライブをオンにします。
  • 全部最大 — 全部を最大（量子ドライブはオン）にします。
  • 読み直す — 船の一覧と 装備 の現在の装備・所持コンポーネントを読み直し、部品を最初の部品に、割り当てを全部最大に、オン/オフをオンに戻します。全部品の候補に入れた品質も消えます。
  • 品質 の欄 — 所持コンポーネントの部品は、装備 で登録した品質を出します（ここでは変えません）。所持船 のときの現在の装備は、所持コンポーネントの同じ部品の品質が 1 通りならその品質を使い、品質の違う行が 2 つ以上あれば品質なしとして計算し、注 に出します。全船 のときの現在の装備は品質なしです。部品の候補が 全部品 のときは、品質の増減のある部品に（「(現在の装備)」の行にも）入力 が出て、その場だけの品質を入れられます（保存しません）。

推定の値

(推定) の付いた値は、ゲームデータの値から計算した推定です。ゲームの中の画面とは確かめていません。推定が入るのは次のところです。

  • 段階の倍率 — ピップを使う部品には、割り当てたピップの段の倍率（powerRanges）を掛けます。値として出るのはクーラーの冷却剤生成量・シールドのシールド再生量・生命維持の生成量で、倍率が 1 でないときに (推定) が付きます。
  • 武器のプールの比例 — エネルギー武器は、プールのピップの割合で武器再生の速さと弾薬容量を比例で減らします。割合が 100% より少ないときは、弾薬容量・武器再生 /秒・1 周・撃ち切るまで・サステイン DPS（と要約のサステイン DPS 合計）に (推定) が付きます。武器全部で 1 つのプールを分け合うことも推定です。プールのピップを出力から引くことも、ゲームの画面では確かめていません。
  • バリスティックとビームの電力 — 電力の割合で変わるかはデータに無いので、プールのピップの割合に関係なく 100% として計算します。割合が 100% より少ないときは、バースト DPS・サステイン DPS（バリスティックは 1 周と撃ち切るまでも）と、要約のバースト DPS 合計・サステイン DPS 合計に (推定) が付き、注 に「電力の割合で変わるかはデータに無い (100% として計算。推定)」と出ます。
  • 熱 — バリスティックは、1 発ごとの熱と冷え方から過熱するまでの発数を出し、過熱の待ちを入れてサステイン DPS・1 周・撃ち切るまでの時間を出します。熱で過熱する武器では、この 3 つにいつも (推定) が付きます。待ち (秒) はデータの値のままで、(推定) は付きません。
  • 品質の重ね方 — 品質の増減は、枠ごとの値を Linear は掛け算、LinearIntegerAdditive は足し算で重ねます。品質を入れていない枠は品質 500 です。品質の増減を使うのは、パワープラントの出力のピップ・クーラーの冷却剤生成量・シールドの最大シールド強度・武器の 1 発のダメージです。パワープラントの出力は足す数（LinearIntegerAdditive）だけを、ほかの 3 つは掛ける数だけを使います。品質の範囲の中では、値を直線で結びます。品質で値が実際に変わったときだけ (推定) が付きます。
  • シールドの基数の上限 — 船のデータにある数のシールドまでしか電力を受けられないとして、行の順で、ピップを割り当てたシールドから数えます。超えたシールドの 結果 は「電力を受けられない (シールドは n 基まで。推定)」となり、シールドの合計も (推定) になります。
  • 最低のピップより少ない割り当てでは動かない、としているのも推定です。

スラスターの電力使用量と冷却剤使用量はデータが無いので出しません。

装備データが古いと感じたら、アップグレード管理 の 装備データを再抽出 を押します。「Data.p4k から船と装備のデータを再抽出します（数分）」と確認が出ます。初回は実行しておくことをおすすめします。

v2.0.12 で「現在の装備」に出ていなかった搭載枠の取り込み漏れを直しました。（綴りの違う搭載枠や、名前では種類が決まらず付いている装備の種類で分かる搭載枠など）。直した内容を反映するには、更新後に 装備データを再抽出 を 1 回実行してください。

13価格キャプチャ — 画面を読んで UEX に送る

ゲーム内の取引ターミナルを画面ごと読み取り、文字認識 (OCR) して UEX に価格を報告する機能です。読み取りと確認まではそのまま使えますが、UEX へ送信するには 設定タブで UEX API キーを登録しておく必要があります。

  1. ゲームでターミナルを開いた状態にします。
  2. 手動キャプチャ (画面全体) を押すか、PrintScreen を押します（PrintScreenホットキー有効 は既定でオンです。切りたいときはチェックを外します）。クリップボードやファイルからの読み取りもできます。

20マップ — 星系図と現在位置

  • 図のデータは、設定タブの インデックス構築 で取り込む星図を使います。無いときは「インデックスが未構築です (設定タブの［インデックス構築］)」と出ます。
  • 図を出すには WebView2 が要ります。使えないときは「（図は WebView2 が必要です）」と出ます。

現在位置 — 現在位置 ボタン

現在位置 を押すと、アプリがゲームのチャットに /showlocation を打ち込み、ゲームがクリップボードに入れた座標を読みます。

  1. ゲームの窓を前に出します。前に出せなかったときは、キーを送らずにやめます。
  2. mobiGlas が開いていないかを、ゲームの画面の下の帯を読んで確かめます。mobiGlas が開いているときは送りません（「mobiGlas が開いているので送りませんでした（閉じてからもう一度押してください）」と出ます）。確かめられないときは、確かめずに送ります。
  3. 今のクリップボードの中身を覚えてから、Enter → /showlocation → Enter を送ります。
  4. クリップボードの座標を読み、クリップボードを元の中身に戻します。アプリの窓を前に戻します。
  5. 現在位置の星系 1 つの表示にして、現在位置を真ん中に出します。
  • 図には現在位置に赤い照準と「現在位置: Orbituary 内 (22:34:42)」のようなラベルが出ます。ほかの場所のラベルには、現在位置からの距離が付きます。
  • 図の右（窓が狭ければ下）に 【現在位置の近く】 が出ます。いちばん上に現在地（例「現在地: Orbituary 内（…）」「現在地: Pyro I 上空 2 Km」）、その下に現在位置の出どころ・星系・近くの惑星の自転の向き、近い順に 10 か所の場所（場所 / 種類 / 距離。場所を押すと 詳細 で開きます）を出します。
  • 送っている途中でゲームの窓が前から外れたときは、そこで止めます。ゲームのチャット欄に打ちかけの文字が残っていたら消してください。
  • 取れなかったときは、ボタンの右に理由が出ます（「ゲーム (Star Citizen) が起動していません」「座標を読めませんでした」など）。
  • 押したとき、今わかっている現在位置の星系が表示している星系と違えば（3 星系の並びのときも）、取る前にその星系 1 つの表示に切り替えます。取れなかったときも切り替わったままです。

自転の補正 — 惑星の近くで押すと位置が正確になる

惑星・衛星のまわりのステーション・都市・地表の場所は、惑星の自転といっしょに回っています。アプリはゲームデータの自転の時間から今の向きを計算して、場所の位置を出しています。

ステーションや都市・惑星の近くで 現在位置 を押すと、その惑星の自転の向きが補正され、マップの位置が正確になります。

  • 惑星・衛星の近くで座標を取ると、今いる場所（ゲームログの今の着陸場所、またはその惑星の中心からの距離と高さが近いステーション・都市など）と取った座標から、その惑星の今の向きを測ります。データの式との差を補正値として覚えます。
  • 補正値は覚えておき、次から使います（アプリを起動し直しても）。マップの図・距離のほか、詳細 タブの【距離】・星系図も補正した向きで計算します。惑星ごとに最新の 1 つを使います。
  • 【現在位置の近く】に「Bloom の自転の向き: 223.27°（データ 223.56°、補正 -0.29°、2026-10-21 18:54 に Game.log の居場所 Orbituary から補正）」のように出ます。補正が無い惑星は「（データから（補正なし））」です。
  • 近くに合う場所が無いときと、地表の場所しか合わずにどれか決められないときは、補正しません。

QT の前後で自動で現在位置を取る

QT の前後で自動で現在位置を取る にチェックを入れると、量子ジャンプのときに 現在位置 と同じやり方で自動で座標を取ります。初めはオフです。

  • 量子ジャンプの目的地を選んだとき（すぐ。取れなければ 3 秒おきにあと 2 回まで。跳んだ後はやめます）と、到着したとき（2 秒後に 1 回）に取ります。
  • ゲームの窓が前にあるときだけ取ります。ゲームの窓を前に出すことも、アプリの窓を前に戻すこともしません。mobiGlas が開いているときは取りません。
  • 前に自動で取り始めてから 10 秒以内は、取りません。
  • 自動で取ったときは、表示の星系と中心は変えません。
  • マップタブが見えていなくても動きます（ゲームログ の読み込みを使います）。

Game.log からの推定位置

ボタンを押さなくても、ゲームログ で読んでいる Game.log から現在位置を推定します。推定位置は赤い白抜きの丸で、ラベルは「推定位置（Orbituary）」のように出ます。

  • 使う順: 今の Game.log の回に 現在位置 で取った座標（その後に死亡・復活も、場所の変化も無いとき）→ 今の着陸場所 → 前に座標を取ったときに覚えた居場所 → 量子ジャンプの到着地点付近。
  • どれにも当たらないときは「現在地: 不明（［現在位置］を押すと座標を取ります）」と出し、図に印は出しません。
  • ゲームログを読めていないときは「ゲームログを読めていないので推定位置は出せません」と出し、前に取った座標だけを出します。

量子ジャンプの線

量子ジャンプの目的地を設定すると、出発地から目的地へ破線と矢印を引き、目的地を目立たせます。【現在位置の近く】に状態の行が出ます。

状態の行とき
QT 目的地 Orbituary: 設定目的地を選んだが、まだ跳んでいない
QT 目的地 Orbituary: 移動中量子ジャンプで移動している（ラベルの距離は目的地からの距離に「、到着後」を添えます）
QT 目的地 Orbituary: 途中で停止（もう一度 QT が必要）移動中に途中で止まった

  • 出発地は、取った座標 → 着陸場所 → 覚えた居場所 → Game.log の出発地の名前の順に決めます。どれにしたかは「出発地: …」の行に出ます。出発地が決まらないときは線を引きません。
  • 契約のビーコンへ跳ぶときは、目的地を選ぶ前 10 分以内の契約の目標の印から、契約の目標（地表）へ線を引きます（「QT 目的地 契約のビーコン（目標: Monox 地表付近）: 設定」。推定です）。30 分以内の契約の目標は、今いる星系の図に橙の旗で出します（新しい 5 つまで）。

  • 到着したとき、ハンガーに入ったとき、着陸場所に着いたときに、線と状態の行を消します。

22Web チャット — ブラウザ・スマホから使う

PC 上のアプリが Web サーバーになり、同じ Wi-Fi のスマホのブラウザからチャットできます。ゲームを全画面で遊びながら、手元のスマホで質問する、という使い方ができます。

起動する

  1. 設定 タブで HTTP ポート:（既定 8099）と HTTPS:（既定 8100）を確認します。
  2. サーバー起動 を押します。HTTP と HTTPS が同時に立ち上がります。
  3. 初回のみ UAC プロンプトが出ます。はい を押すと、証明書のインストール・HTTPS ポートの登録・ファイアウォールの開放を自動で行います。続けて 証明書インストール確認が 3 回出るので、すべて はい を押します。
  4. ブラウザで次の URL を開きます。
    • PC から: http://localhost:8099/
    • スマホなど LAN 内の機械から: http://192.168.x.x:8099/
    • スマホでマイクを使う場合: https://192.168.x.x:8100/

192.168.x.x の調べ方: PC でコマンドプロンプトか PowerShell を開いて ipconfig を実行します。「Wi-Fi」または「イーサネット」の IPv4 アドレス（例 192.168.1.15）がこの PC のアドレスです。アプリの画面にも表示されます。スマホは同じ Wi-Fi につないでください。

スマホでマイクを使う

ブラウザは localhost 以外の HTTP ではマイクを許可しません。音声入力を使うときだけ、次の手順で HTTPS 側 (8100) を使えるようにします。マイクを使わないなら http://192.168.x.x:8099/ のままで構いません。

  1. スマホのブラウザで http://192.168.x.x:8099/cert を開きます。
  2. ［証明書をダウンロード］をタップしてインストールします。
    • iPhone: 設定 → 一般 → VPN とデバイス管理 → プロファイルをインストール → 設定 → 一般 → 情報 → 証明書信頼設定 → 有効化
    • Android: 設定 → セキュリティ → 証明書のインストール → CA 証明書 → ダウンロードしたファイルを選択
  3. https://192.168.x.x:8100/ を開きます。マイクが使えるようになります。

「この接続ではプライバシーが保護されません」と出たとき。自己署名証明書を使っているためで、異常ではありません。詳細設定（iPhone Safari なら 詳細を表示）から続行してください。一度許可すれば、同じブラウザでは次から出ません。通信自体は暗号化されています。

証明書はこの PC 専用の自己署名証明書で、外部の認証局は使いません。不要になったらスマホから削除してください。ファイアウォールには「SC Japanese Assistant HTTP」「SC Japanese Assistant HTTPS」というルール名で登録されます。

音声で読み上げさせる

  • PC で VoiceVox を起動しておきます（無料）。既定の接続先は http://localhost:50021 です。
  • 画面下の入力バーにあるスピーカーボタンを押すと読み上げがオンになります。オフのときは 🔈、オンにすると緑色の 🔊 に変わります。押さないかぎり読み上げません。
  • オンのときは、質問を送ると「おまちください」、回答が来ると「お待たせしました」と AI が作った要約を読み上げます。
  • 画面右上の歯車アイコンから話者（キャラクター）を変えられます。アプリの設定タブの VoiceVox 話者ID でも指定できます。
  • 読み上げの速さは、アプリの設定タブの VoiceVox 速度（0.5〜2.0 倍、既定 1.0 倍）で決めます。設定を保存 を押したあと、ブラウザでページを読み込み直すと反映されます。

データ API（読み取り専用）

Web チャットサーバーを起動していないと、データ API は使えません。設定タブの サーバー起動 を押してから呼んでください。アプリを起動したときに自動で起動させるには 自動起動 にチェックを入れます。

Web サーバーを起動している間は、詳細タブ・交易・契約などのデータを JSON か HTML で読み出せます。ほかのツールやスクリプトから使うためのもので、すべて GET の読み取り専用です（DB には書き込みません）。データは画面と同じ読み方で出します。

  • ポート: Web チャットと同じです。http://localhost:8099/api/…、HTTPS なら https://localhost:8100/api/…（LAN の他の機械からは 192.168.x.x）。
  • 形式: format=json（既定）か format=html。それ以外は 400 になります。
    • JSON の一覧は { "total": 全体の件数, "count": 返した件数, "items": [ … ] } です。total は limit・offset を通す前の件数、count は返した件数です。
    • JSON の詳細は { "record", "name", "text" } です。項目はアプリの中のデータの項目名のままです。
    • HTML の一覧は表、詳細は詳細タブと同じ見た目のページです。詳細の中のリンクは /api/detail?record=…&format=html に移ります。
  • 件数: 一覧には limit（最大件数。1 以上の整数）と offset（飛ばす件数。0 以上の整数）を付けられます。付けなければ全件です。/api/search の limit だけは 1〜1000 です。
  • 生の JSON: 契約の一覧の RawJson（ゲームデータの生の JSON。とても大きい）は、既定では出しません。raw=1 を付けたときだけ出します。
  • エラーは形式にかかわらず { "error": "…" } で返します。引数の誤りは 400、個人のデータをこの PC 以外から読もうとしたときは 403、見つからないとき・/api/ で始まる知らないパスは 404、GET 以外は 405、データがまだ無いときは 503、アプリの中の失敗は 500（"内部エラー"。中身はアプリのログ app_log.txt に残します）。

個人のデータはこの PC からだけ。パスが /api/my/ で始まるもの（所持船・所持品・Hangar・ゲームログなど）は、要求元がこの PC（ループバック）で、しかも Host ヘッダーのホスト名が localhost・127.0.0.1・[::1] のどれか（ポートは問わない）のときだけ返します。それ以外は 403 になります。個人のデータの応答には CORS のヘッダーを付けません。

ゲームのデータのルートに混ざる個人のデータも同じ条件です。/api/blueprints の所持（Owned）・在庫（StockText・stockText）・手持ち（haves）、/api/detail と /api/missions/detail の【ブループリント】の節の「在庫」「所持」の行と「手持ち」の欄は、上と同じ条件（この PC から、Host が localhost・127.0.0.1・[::1]）のときだけ画面と同じに出し、そのときの応答には CORS のヘッダーを付けません。条件に合わない要求（LAN の他の機械から・Host が違う）には、個人のデータを出さずに CORS のヘッダーを付けて返します。ほかのゲームのデータのルートは、いつも CORS のヘッダーを付けます。

26鉱石 — 資源の在庫と売買・採掘の記録

列内容

売買の記録・採掘の記録

どちらも読むだけの表です。検索・Select・並べ替え・コピーは表の共通の操作のとおりです。時刻はこの PC の時刻で出します。

表列
売買の記録時刻 / 種類（購入 / 売却）/ 資源 / 量 SCU / 合計 aUEC / 単価 / 店 / 結果（成功なら 成功、失敗はゲームの結果の文字）/ 仕入れ / 利益 / 利益率
採掘の記録時刻 / 資源 / 量 / 単位 / 品質 / 方法（手掘り / 船 / GEO / 手入力）

Select が出ないのは、売買の記録の 時刻 / 量 SCU / 合計 aUEC / 単価 / 仕入れ / 利益 / 利益率 と、採掘の記録の 時刻 / 量 です（採掘の記録の 品質 には出ます）。

利益の計算

  • 同じ資源の成功した買いを時刻の順に、先に買った分から売りに当てます（先入れ先出し）。
  • 仕入れ は当てた買いの単価 × SCU の合計、利益 は売りの合計 − 仕入れ、利益率 は利益 ÷ 仕入れです（当てた買いが無い・仕入れが 0 なら利益率は空欄）。
  • 売りより後の買いは当てません。買いが足りない分は仕入れ 0 として数えます。失敗した行は計算に入れません。

ゲームログ・BP との関係

  • 売買と採掘の記録は ゲームログ の行から自動で入ります（→ 25）。新しい記録が入ると、利益を計算し直して在庫へ入れます。
  • 在庫を変えるのは 2026/10/15 23:01（日本時間）以降の記録だけです。それより前の記録は表に残しますが、在庫は動かしません。
  • 在庫への入れ方: 売買は成功した行の買いで足し、売りで引きます（品質は不明、単位は SCU）。失敗した行・SCU の無い行・資源の分からない行は在庫を変えません。採掘は行の量・単位・品質で足します。資源が分からない採掘の行も在庫に入れません。在庫は 0 より下には下げません。
  • ゲームログ の成功した売却の行に出る利益（/ 利益 +n aUEC (n%)）は、ここの売買の記録で計算したものです。
  • BP タブの 在庫 の欄は、ここの在庫と照らした結果です（→ 27）。
  • 在庫・売買の記録・採掘の記録の 資源 の列をダブルクリックすると、その資源を 詳細 タブに出します（採掘できる場所の表。→ 鉱石（資源）の詳細）。資源の分からない行では何もしません。ほかの列のダブルクリックの動きは今までどおりです。

29困ったときは

ゲームが日本語にならない

次の順に確認してください。

  1. 上部の GamePath が、いま遊んでいるチャンネル（LIVE / PTU など）を指しているか。
  2. 翻訳 タブで 日本語化 → 実行 を行ったか。アプリを更新したあとは毎回必要です。
  3. ゲームフォルダに data/Localization/japanese_(japan)/global.ini ができているか。
  4. ゲームフォルダの user.cfg に g_language = japanese_(japan) の行があるか。
パッチが来たら英語に戻った

ゲーム側のファイルがパッチで置き換わったためです。新しいパッチを読み取る → 日本語化 → 実行 を行ってください。これだけで日本語に戻ります。増えた英語を自分で訳したい場合にだけ、間に AI翻訳 を挟みます。

訳がおかしい / 訳さないでほしい語がある

翻訳エディタでその行を直接書き換えると manual になり、再翻訳では上書きされず、同梱 DB で作り直したときも引き継がれます。毎回同じ語を直しているなら、用語集に登録して 一括置換 (翻訳済みテキストに適用) を実行するほうが早いです。ただし一括置換だけは例外で、手で直した行も置き換えます。英語のままにしたい語は、翻訳エディタでその行を選んで 全て原文 を押してください。

スマホからつながらない
  1. PC とスマホが同じ Wi-Fi につながっているか確認します。
  2. 設定タブで サーバー起動 を押したか、初回の UAC プロンプトで はい を選んだか確認します。
  3. PC で ipconfig を実行して IPv4 アドレスを確認し、そのアドレスでアクセスします。
  4. マイクを使うなら https:// と 8100 番であることを確認します。
スマホでマイクのボタンが反応しない

HTTP（8099）で開いている可能性が高いです。ブラウザはセキュアな接続でないとマイクを許可しません。スマホでマイクを使うの手順で http://192.168.x.x:8099/cert から証明書を入れたうえで、https://192.168.x.x:8100/ で開き直してください。証明書の警告は 詳細設定 から続行します。それでもだめな場合は、ブラウザのサイト設定でマイクがブロックされていないか確認します。

船の初期装備が表示されない / 古い

船舶管理 > アップグレード管理 の 装備データを再抽出 を実行してください。数分かかります。初回は実行しておくことをおすすめします。

とくに武器 (ガン) のデフォルトが空欄のままの場合は、再抽出が必要です。古いバージョンで作られたデータには、ジンバル越しに積まれている武器が入っていません。再抽出すると、ジンバルの下に実際の武器が出るようになります。

装備の購入先が「取得中…」のまま / 出てこない

購入先は起動のたびにバックグラウンドで UEX から取り込みます。回線にもよりますが全部そろうまで十数秒から 1 分ほどかかるので、少し待ってからもう一度マウスを乗せてください。ネットにつながっていないときは前回取り込んだ内容がそのまま出ます。船に最初から付いている装備は店で売られていないことが多く、その場合は待っても 購入先の登録がありません のままです。UEX の API キーは要りません。

My Hangar 同期でログインできない

内蔵ブラウザ内で RSI にログインしてから ログイン完了 → 再試行 を押してください。WebView2 ランタイム（Evergreen）が入っていない環境では内蔵ブラウザが表示されません。Windows 10 / 11 には通常入っていますが、入っていない場合は Microsoft から導入してください。

翻訳データを全部やり直したい

設定 タブの 翻訳DBクリア (全翻訳データ削除) を実行してから、新しいパッチを読み取る を押します。手で直した訳も消えます。実行前に エクスポート (バックアップ) を取ってください。
